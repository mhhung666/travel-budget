## 保留決策與限制

- 新上傳比對原始 File 的 `sourceHash`，歷史盤點比對儲存 JPEG 的 `storedHash`；兩者不能互換。相似畫面、裁切、重匯出不自動視為相同檔。
- 先登記持久工作再簽上傳 URL；固定 uploadId／key，重試先查結果，finalize 與清理共用交易保護。
- 無引用物件透過既有退役工作清理，保留 tombstone；不能因 PUT 失敗就直接刪檔，也不能用 TTL 先丟掉未完成工作。
- 正式 storedHash 回填未執行，也未接入新上傳；不包含感知比對、歷史合併、關頁續傳、bytes 百分比及其他附件入口。
- 手機／慢網、CORS 與 cron 實際排程尚未完整端到端驗收。18 張近期照片未查重；刪除物件的第二次清掃由既有工作接續，不記為已完成。
