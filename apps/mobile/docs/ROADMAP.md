## 階段 4：離線核心（D1 → D2 → D3）

### D1：已實作，待獨立驗收

已完成 SQLite 草稿保存、修訂／世代保護、續填／捨棄與四語提示，以及重新授權／選項驗證／新預覽後原子接回 C。開發測試涵蓋真 SQLite 檔案重開、舊版升級、亂序保存、捨棄競態、失敗與子程序交接當機，並回歸 C 的同 UUID 恢復；成果與驗證見 [archive](archive/README.md)。兩平台驗收由其他人執行，尚未計通過，核對項目見 [本機驗收](LOCAL_ACCEPTANCE.md#d1-草稿驗收交接)。

D1 只從既有線上登入／旅行入口續填，已開啟表單可斷網保存本機輸入；離線冷啟動與入口快取留給 D2。沿用現有 HTTP 契約，尚無自動送出、多筆佇列或手機分帳算法；C 暫緩項目仍待驗。

### D2：離線可進入與續填

- 補最小旅行入口與成員選項快照，標示最後更新時間；私人資料按帳號／環境隔離，已知撤權立即隱藏。只快取草稿必要資訊，不持久化整份 Query cache。
- 先定義離線冷啟動的受限模式：可讀本人本機草稿不代表 session 已驗證；送出前必須恢復線上登入與旅行授權，不放寬既有 API 保護。
- 驗收飛航模式、強制關閉／重啟、登入到期及 A→B→A；連線後成員異動須重新預覽與確認。此階段只存草稿，不自動寫入帳務。

### D3：確認後的待送佇列

- 開始前先補契約：目前均分只能在線上由後端預覽。離線首次確認如何取得可接受的分攤、成員變更如何重新確認，須先定案；手機不得另寫分帳演算法，也不能悄悄改動已確認內容。
- 定義草稿、已確認待送、送出中、結果不明與需處理狀態；只允許修改／捨棄尚未送出的內容，結果不明的紀錄保留原 UUID／payload。草稿不會因恢復連線自動變成提交。
- 先做 App 前景且連線時的同步：同一請求序列處理、尊重 Retry-After、登入失效暫停、撤權保留紀錄並提示；OS 背景排程另排。
- 驗收多筆佇列、中途斷線、已提交後丟回應、重啟、409、429、refresh 失敗、撤權與換帳號；查回或重試都使用原 UUID／payload，DB 與副作用只產生一次。

## 交付規則

- 實作與驗收分開；交接只需範圍、必要決策、實際測試結果與未驗項目。驗收分「通過／需修正／受環境限制未驗」，不以 mock 或 bundle export 取代裝置證據。
- 執行受影響測試與 Mobile check／export；跨 workspace 交付依 [開發規範](../../../docs/DEVELOPMENT.md) 執行根檢查、測試與 build。契約改動產生並檢查 OpenAPI；資料庫寫入用隔離真 DB 驗證。
- 更新受影響的現況文件與根 `changelog.md`；已完成項目合併至 [archive](archive/README.md)，roadmap 保留待辦，細節查 Git，不新增逐輪報告。commit／push／版本與發布依 repository 規則及使用者指示處理。
