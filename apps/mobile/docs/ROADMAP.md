## 階段 4：離線核心（D1 → D2 → D3）

### D1：下一個功能交付——草稿保存

- 範圍：每個環境／帳號／旅行先保留一份可編輯草稿，保存表單輸入；提供續填、明確捨棄與儲存失敗提示。沿用 SQLite，草稿與 C 的待確認紀錄分開，不保存 token 或把舊預覽當作有效分攤。
- 恢復：重新驗證金額／日期，連線後刷新成員與分類；已失效的付款人／成員要求重新選擇，重新預覽後才可確認。登出或換帳號隱藏草稿，同帳號回來可續填；已知撤權時隱藏私人內容，直到授權重新確認。
- 交接：草稿轉成提交時，先可靠保存原 UUID／凍結內容，再標記草稿已交接；當機或本機清理失敗不得留下可再次提交的同一份草稿。已有待確認紀錄時，先處理原請求。
- 驗收：真 SQLite 測試保存／恢復／捨棄、儲存失敗、帳號／環境隔離與交接當機；iOS／Android 操作「填寫 → 關閉 → 重開 → 續填 → 預覽 → 提交」，DB 只有一筆。新介面四語與鍵盤操作一併驗收。

### D1 實作順序與交付邊界

1. **儲存與升級**：沿用現有 SQLite 資料庫，新增草稿表與集中版本升級，保留既有 pending 紀錄；欄位包含範圍、原始輸入、更新時間與修訂號。允許保存未填完或暫時無效的輸入，不存預覽、分攤結果或 token。以序列寫入／修訂檢查防止晚到存檔覆蓋新輸入，明確呈現保存中、已保存與失敗；只有落盤成功才保證重啟恢復。
2. **續填介面**：在既有新增入口提供續填／捨棄；保存說明、金額文字、日期、分類、付款人與分攤成員。離開與切背景嘗試完成存檔；還原不得覆蓋已開始的新輸入，捨棄後晚到存檔不能讓草稿復活。四語、字級、深淺色與錯誤提示同批完成。
3. **接回 C**：先重新取得旅行授權與選項，失效選項要求修正，不靜默替換；取得新預覽並確認後，在同一 SQLite 交易建立 pending UUID／凍結內容並交接草稿，再由 `ExpenseEntry` 送出。交易失敗不送 HTTP；結果不明沿用 C；明確拒絕才安全恢復可編輯草稿，成功後舊草稿不得復活。
4. **獨立驗收**：真 SQLite 覆蓋舊版升級、亂序存檔、捨棄競態、儲存失敗、帳號／環境隔離與交接各當機點；兩平台驗證續填、強制關閉重開、換帳號、成員失效與提交後丟回應，核對 DB 僅一筆。跑 Mobile test／check／export，回歸 C 核心；交接只報修改範圍、測試結果與未驗項目。

D1 只從既有線上登入／旅行入口續填；預計允許已開啟的表單在斷網時保存本機輸入，離線冷啟動與旅行入口快取留給 D2。沿用既有 HTTP 契約，不增加自動送出、多筆佇列或手機分帳算法；C 暫緩項目仍列待驗，不作為 D1 已通過的證據。

### D2：離線可進入與續填

- 補最小旅行入口與成員選項快照，標示最後更新時間；私人資料按帳號／環境隔離，已知撤權立即隱藏。只快取草稿必要資訊，不持久化整份 Query cache。
- 先定義離線冷啟動的受限模式：可讀本人本機草稿不代表 session 已驗證；送出前必須恢復線上登入與旅行授權，不放寬既有 API 保護。
- 驗收飛航模式、強制關閉／重啟、登入到期及 A→B→A；連線後成員異動須重新預覽與確認。此階段只存草稿，不自動寫入帳務。

### D3：確認後的待送佇列

- 開始前先補契約：目前均分只能在線上由後端預覽。離線首次確認如何取得可接受的分攤、成員變更如何重新確認，須先定案；手機不得另寫分帳演算法，也不能悄悄改動已確認內容。
- 定義草稿、已確認待送、送出中、結果不明與需處理狀態；只允許修改／捨棄尚未送出的內容，結果不明的紀錄保留原 UUID／payload。草稿不會因恢復連線自動變成提交。
- 先做 App 前景且連線時的同步：同一請求序列處理、尊重 Retry-After、登入失效暫停、撤權保留紀錄並提示；OS 背景排程另排。
- 驗收多筆佇列、中途斷線、已提交後丟回應、重啟、409、429、refresh 失敗、撤權與換帳號；查回或重試都使用原 UUID／payload，DB 與副作用只產生一次。

## 交付規則

- 實作與驗收分開；交接只需範圍、必要決策、實際測試結果與未驗項目。驗收分「通過／需修正／受環境限制未驗」，不以 mock 或 bundle export 取代裝置證據。
- 執行受影響測試與 Mobile check／export；跨 workspace 交付依 [開發規範](../../../docs/DEVELOPMENT.md) 執行根檢查、測試與 build。契約改動產生並檢查 OpenAPI；資料庫寫入用隔離真 DB 驗證。
- 更新受影響的現況文件與根 `changelog.md`；已完成項目合併至 [archive](archive/README.md)，roadmap 保留待辦，細節查 Git，不新增逐輪報告。commit／push／版本與發布依 repository 規則及使用者指示處理。
