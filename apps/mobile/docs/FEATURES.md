# 現有功能

已實作「既有帳號登入 → 旅行列表 → 旅行摘要 → 支出清單／明細 → 結算」的唯讀流程，以及線上新增支出（僅 TWD、勾選成員均分）與不確定結果恢復；後端位於同一 repository 的 `apps/web`。手機與後端共用 `@travel-budget/contracts` API schema。這是程式實作狀態，不代表已部署或已通過真機驗收；模擬器驗收成果見 [archive](archive/README.md)，C 剩餘裝置項目見 [本機驗收](LOCAL_ACCEPTANCE.md#尚未完成的驗收)。

- 使用網站既有的帳號／密碼登入；access token 僅存記憶體，refresh token 存在以 API 環境隔離的 SecureStore。
- 重開 App 時更新憑證並恢復登入；登入過期／撤銷會清除私人快取。更新憑證採單一併發請求，每次 API 最多因 401 更新並重送一次。
- 更新後的 refresh token 若無法寫入 SecureStore，會清除不可再使用的舊憑證與私人快取，並嘗試撤銷新憑證；清除成功後回到登入頁，儲存空間仍無法清除時顯示錯誤並提供重試。舊登入恢復／登出結果不會覆蓋後續登入。
- 旅行列表顯示名稱、目的地、日期、個人分攤金額與狀態。旅行中優先，其次即將出發；個人封存旅行排最後。每頁 20 筆，支援載入更多與下拉更新。
- 旅行摘要顯示日期、角色、人數、支出筆數、本人分攤花費、應收／應付、今日全團花費及本人的總預算。金額皆為後端既有 TWD 計算結果。
- 旅行摘要有「支出」「結算」入口。支出清單依日期、建立時間由新到舊，每頁 20 筆（游標分頁），支援載入更多與下拉更新（只重讀最新一頁）；每筆顯示日期、說明、付款人與 TWD 金額，外幣另顯示原幣金額。
- 單筆明細顯示分類、付款人、TWD 金額、原幣金額／匯率與各成員 TWD 分攤；可讀 Web 已有的外幣、非均分、虛擬成員與歷史資料，金額沿用後端既有計算。附件內容與下載入口不在手機顯示。返回按鈕回到該旅行的支出清單，已有清單則沿用既有頁面。
- 結算顯示總支出、成員餘額（已扣除已登記還款）、建議轉帳（標示尚未付款，本人相關者優先）與既有還款紀錄；沒有支出、已全部結清與尚有欠款是三種不同狀態。
- 失去成員資格或資源不存在時，旅行摘要、支出與結算畫面顯示不可用並隱藏已快取的私人資料；之後重試遇到逾時、斷線或 5xx 也保持隱藏，直到成功讀取證明權限恢復。一般網路故障（沒有先前拒絕）仍可看到合法的舊資料。
- 支援載入、空資料、錯誤、重試與離線提示；回前景重新確認連線，前景／網路恢復時更新過期查詢，離線暫停的首次讀取可繼續。已載入資料只保留於本次執行的記憶體。
- 四語系（繁中、簡中、英文、日文）、深淺色、安全區域、文字縮放、鍵盤表單與無障礙按鈕標籤；新增表單的單選／多選項目提供勾選狀態，欄位提供錯誤朗讀提示，Android 動態錯誤使用 polite 通知。
- 登出先撤銷伺服器 session，再刪除 SecureStore 及取消／清除私人查詢；重複點擊合併為一次登出。無法連線時保留登入並提示重試，不宣稱遠端已登出。
- 新增支出（旅行摘要與支出清單各有「新增支出」入口）：填寫說明（最多 200 字）、TWD 金額（以文字輸入，只接受數字與至多兩位小數，不用 `parseFloat` 猜測；0.01 至 1,000,000,000）、日期（date-only，須是真實日曆日，有前一天／今天／後一天按鈕，不經 UTC 換算）、分類、付款人（預設本人，可不參與分攤）與分攤成員（預設全部成員）。按「預覽分攤」由後端以固定成員順序均分（100 元三人為 33.34／33.33／33.33），手機不計算金額；表單輸入一改，舊預覽立即失效並取消進行中的請求，晚到的舊回應不會覆蓋新輸入，改回原值也要重新預覽；重新預覽時先捨棄舊結果，確認只對應最新一次成功的預覽。預覽被拒（403／404，例如已被移出旅行）時，整個畫面只留下「找不到旅行」提示，不再顯示成員姓名、分攤或確認，之後的斷線或逾時也不會讓它重新出現，直到重新讀取成功。確認後以預覽的分攤原樣送出。離線時不能預覽或送出。
- 支出草稿（D1）：每個 API 環境／帳號／旅行保留一份 SQLite 草稿，保存原始說明、金額文字、日期、分類、付款人與分攤成員，未填完或暫時無效的輸入也可保存。畫面顯示保存中／已保存在此裝置／保存失敗，失敗可重試；只有落盤成功的輸入保證重啟恢復。離開／切背景會嘗試完成保存，回到新增入口可明確續填或捨棄；捨棄後的新草稿依最新已載入的成員選項初始化。換帳號隱藏原帳號草稿，同帳號回來仍可續填；重新進入須成功讀取旅行選項確認授權，已知撤權時隱藏私人內容。已開啟表單可斷網保存本機輸入；離線冷啟動與旅行入口仍留給 D2。
- 續填不恢復舊預覽：重新檢查金額／日期，預覽前刷新成員與分類；失效付款人／分類需重新選擇，失效分攤成員需明確移除，不靜默改動。使用者取得新預覽並確認後，在同一 SQLite 交易建立 C 的 UUID／凍結請求並標記草稿已交接；交易失敗不送 HTTP。交接後不能再續填或捨棄該草稿，結果不明只查詢或重試原 UUID；明確拒絕才原子恢復原始輸入，成功後舊草稿不得復活。
- 確認的當下凍結內容並產生一個 UUID，防止雙擊重複送出；401 自動更新憑證後的重送、手動重試與結果查詢一律沿用同一個 UUID 與內容。只有伺服器明確回成功才顯示「已儲存」，之後清單、明細、旅行摘要與結算會失效並重讀；重讀失敗只顯示更新失敗與重新整理，不要求重新記帳。儲存後可查看明細、再新增或返回該旅行的支出清單；清單已在導覽堆疊中時返回既有清單。伺服器在寫入前明確拒絕（400 等）時回到編輯，修正後是新的提交。
- 待確認紀錄：送出前先把環境、帳號、旅行、UUID、凍結內容與狀態存入裝置的 SQLite（`expo-sqlite`，不存 token，獨立於可清除的查詢快取），存不進去就不送出。逾時、斷線、5xx、回應遺失或帳號／旅行權限問題都不會清除紀錄；畫面顯示「尚未確認的支出」，只能「查詢結果」或「以原內容重試」（同一個 UUID，後端冪等，不會重複記帳），確認前該旅行不能新增其他支出。App 啟動、回前景與恢復連線時自動以同帳號查詢結果，找到就移除紀錄並更新各畫面（只查詢，不自動重送）。登出或換帳號後，其他帳號看不到也送不出前一個帳號的紀錄，同帳號回來可繼續；無法再存取旅行時保留紀錄並提示無法確認，不假稱失敗；409 會查明原請求，不換 UUID。離開畫面不會取消或清除已送出的請求。Web 預覽沒有登入也沒有 SQLite。

Web 匯出只提供介面預覽，登入明確停用；不把憑證降級存到 localStorage。原有網站仍是完整 Web 用戶端。

尚未提供手機註冊、建立／加入旅行、外幣或非均分輸入、編輯／刪除支出、登記還款、行程編輯、附件、離線建立與背景同步（待確認紀錄只保障線上確認過的提交，沒有離線首次送出、批次自動重送或背景排程）、推播或帳號刪除。未送出的草稿保存在此裝置，但尚無離線冷啟動入口、多筆待送佇列或自動提交。摘要中的後續功能說明不會假裝是可操作入口。新增支出使用的 API 見 [後端契約](BACKEND_CONTRACT.md)。
