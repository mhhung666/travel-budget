## 2. 記帳表單可以更快，尤其是改分帳時

現況：先看到「快速記帳」與 AI 說明才到金額；付款人與分帳雖有摘要，展開後卻與日期、行程日、標籤、匯率混在同一區。
實際情境「這餐只有兩個人吃」，需要進入很長的詳細資訊區才能修改。

建議的欄位順序：

| 順序 | 內容 |
| --- | --- |
| 最上方 | 旅行名稱，可切換 |
| 主要輸入 | 金額＋幣別、描述、分類 |
| 直接可改 | 我付款／今天／全員均分 |
| 次要入口 | 一句話記帳、掃描收據 |
| 更多設定 | 匯率、標籤、關聯行程日 |

另外：從首頁選完旅行後，表單標題只有「新增支出」，建議持續顯示正在記哪一趟，降低記錯帳本的機會。
既有的「金額自動取得焦點」值得保留。

### 已完成（2026-09-16，待部署）

- 表單順序改為：標題下方常駐「記到：旅行名稱」→ 金額＋幣別（保留自動聚焦）→ 描述 → 分類
  → 付款人（標示「（我）」）＋日期直接露出 → 分帳摘要列，點一下即展開分帳明細
  → 快速記帳（一句話／掃描收據）→「更多設定」（匯率、標籤、關聯行程日；編輯時含收據）。
- 全域「記一筆」有兩趟以上可選時，表單提供「切換旅行」回到旅行選擇。
- 外幣換算結果移到金額下方；缺匯率時「更多設定」強制展開，避免錯誤被藏起來。
- 編輯既有支出不再整區展開：非均分才展開分帳；有外幣、標籤、行程日或收據才展開更多設定。
- 本機瀏覽器（桌面＋390px 手機寬）驗證：付款人／日期／分帳摘要不需展開即可見，
  分帳可一步展開，切換旅行後標題更新為新旅行。

## 3. 行程頁的第一屏應更快看到行程

現況上方依序為：全站導覽 → 旅行標題 → 兩層分頁 → 預算列 → 行前提醒 → 旅行資訊 → 工具列；
桌面畫面上第一個活動已接近畫面底部。「還有 0 項待辦」占了明顯區塊但幫助有限。

建議：

- 目的地、日期合併到旅行標題附近。
- 行前提示縮成一列，例如「10 天後出發 · 清單已完成」。
- 加入固定的日期切換（Day 1、Day 2…），避免往下找。
- 旅行途中優先顯示今天與下一個活動。
- 每筆活動的編輯、移除收進「⋯」。

總評：目前視覺較像在「管理行程資料」，調整後會更像旅行當下查看的工具。

### 已完成（2026-09-17，待部署）

- 「行前提醒」與「旅行資訊」兩張卡合併為一張精簡卡：第一列目的地＋日期（編輯、展開描述），
  第二列階段標籤＋一句狀態——行前「10 天後出發 · 清單已完成／清單還有 N 項」、
  旅中「Day 3 · 下一個：14:00 活動 · 今日花費」＋看今天／記一筆、旅後「待結算 NT$…／已結清」。
  清單與結算資料載入前不顯示該段，避免閃出「已結清」。窄螢幕狀態句獨佔一列，不被按鈕截斷。
- 行程有兩天以上時，出現黏在行程空間頁首下方的 Day 1／Day 2… 日期列：顯示日期、旅中標示「今天」，
  捲動時標出目前所在日，點選捲到該日且標題不被遮住。
- 活動的帶入成就／編輯／移除收進「⋯」（已帶入成就仍顯示獎章）；行程日的編輯／刪除也收進「⋯」，
  標題列只留「新增活動」。工具列按鈕改小尺寸。
- 本機瀏覽器（有 5 天、每天 5 個活動、旅中的旅行；量測時以關閉提示卡代表移除後狀態）量測第一個活動底部位置：
  桌面 1280×800 由 896px → 698px（進入第一屏）；手機 390×844 由 871px → 649px。
  兩種寬度點 Day 4 後標題在日期列下方、目前日正確標示；「⋯」可開編輯與移除確認。
- 移除行程頁的「先完成這兩步」首次使用提示卡：新旅行尚無支出／旅伴時會把活動推出桌面第一屏，
  且其兩個動作已有常駐入口（全域「記一筆」、行程設定的邀請連結）。`activation_step: invite_shared`
  改在設定頁邀請連結的複製按鈕（[ShareCode](../src/components/trips/ShareCode.tsx)）記錄。

## 4. 統計的位置與尋找路徑不一致

單趟旅行的「群組統計」目前在「結算」底下，但想知道「交通花多少、哪天最貴」通常會先點支出。
建議保留現有主要分頁，只調整第二層：

| 主要分頁 | 第二層 |
| --- | --- |
| 行程 | 每日行程、隨手記、清單 |
| 支出 | 支出明細、花費分析 |
| 相簿 | 維持現有功能 |
| 結算 | 待收／待付、還款紀錄 |

個人統計則繼續負責跨旅行比較，兩者分工更直覺。

### 已完成（2026-09-17，待部署）

- 「支出」主分頁新增子分頁「支出明細／花費分析」；花費分析即原單趟群組統計，URL 維持 `/trips/[id]/stats`，
  既有深連結與公開分享不受影響。
- 「結算」不再有子分頁列：待收／待付與還款紀錄本來就在同一頁，拆成兩個路由只會多一次點擊，故刻意不拆。
- 分頁名稱四語系同步（移除不再使用的「結算方案」字串）；分頁契約測試改守新名稱。

## 5. 結算畫面：按鈕依身分改字

「你應收 NT$1,972」的大摘要與付款人→收款人方向都清楚；但身為收款人時按鈕仍寫「標記已付」，語意需要停頓判斷。

- 我是收款人：**確認已收到**
- 我是付款人：**我已付款**
- 「總應付」改成「應分攤」、金額格式統一：已隨第 1 項完成。

### 已完成（2026-09-17，待部署）

- 結算方案每筆轉帳的按鈕依目前登入者身分改字：收款人「確認已收到」、付款人「我已付款」；
  與自己無關的轉帳（其他成員之間）維持中性的「標記已付」。按下後的行為不變（開啟登記還款）。
- 四語系同步新增 `settlement.confirmReceived`／`settlement.iPaid`；
  [settlementPlanLabels.test.tsx](../src/__tests__/settlementPlanLabels.test.tsx) 守三種身分的按鈕文字。

## 6. 首頁應呈現「這趟現在怎樣了」

旅行卡片目前只有名稱、目的地、日期、人數；可辨識帳本但看不出狀態。
另外，兩趟尚未出發的旅行都放在「進行中」，語意偏差。

建議：

- 分頁改為「目前旅行／已封存」，卡片標示「即將出發、旅行中、待結算」。
- 卡片加上「我的花費／預算」小摘要。
- 最近即將出發或正在旅行的那趟優先排序。
- 卡片直接提供「記一筆」與「查看行程」。

這比單純加大封面圖片更能提升首頁實用性。

### 已完成（2026-09-17，待部署）

- 分頁改名「目前旅行／已封存」（仍只在有封存旅行時出現）。
- 旅行中與即將出發的旅行抽出置頂為「旅行中與即將出發」分組：旅行中在前，即將出發依出發日由近到遠；
  其餘仍依年份分組。
- 卡片狀態標記：即將出發 · N 天後／旅行中 · Day N／待結算／已結清。結束後的判斷看「我的」結算餘額
  （已抵銷還款），不是整團是否結清；沒有任何花費的旅行不標「已結清」；封存與無日期旅行不標。
- 卡片摘要：待結算時顯示「你應收／你應付 NT$…」，否則「我的花費 NT$…（/ 預算 NT$…）」。
- 卡片動作列：「記一筆」直接開該旅行的新增支出表單（與全域記一筆同一元件）＋「查看行程」；
  待結算時「記一筆」換成「查看結算」。封存旅行不顯示動作列。
- 資料：`getTrips` 多帶 `my_spent`／`my_balance`，由 [tripListSummary.ts](../src/lib/tripListSummary.ts)
  以一次支出聚合＋一次還款查詢算出，不隨旅行數增加查詢次數；
  [moneyAggregation 整合測試](../src/__tests__/moneyAggregation.integration.test.ts) 守它與結算頁同值（含部分還款）。
  持久化快取形狀改變，`PERSIST_BUSTER` 升到 v10。
- 本機瀏覽器（桌面 1280＋手機 390，五趟旅行涵蓋各狀態）驗證：分組順序、標記、摘要金額正確，
  「記一筆」開出「記到：成都美食」表單，手機無橫向捲動。未另外點選「已封存」分頁。

## 7. 零星小項（容易修、也有感）

- 建立旅行的展開按鈕寫「加入日期、描述與旅伴」，展開後只有描述與日期；文案應與實際內容一致。
- 群組統計的「每日花費」按關聯行程日整理，趨勢圖則用付款日期；建議明確標示「依行程日／依付款日」。
- 個人統計對尚未出發、只有 3 筆支出的旅行已顯示「交通占 87%」等洞察；建議補「目前為行前支出」。
- 保留青綠主色，但減少卡片包卡片與說明文字，讓金額、活動名稱與主要按鈕更突出。

### 已完成（2026-09-17，待部署）

- 建立旅行展開按鈕改為「加入描述與日期（選填）」；已載入好友清單且有好友時才寫「加入描述、日期與旅伴」。
- 群組統計：每日花費卡加註「依行程日整理；跨多天的支出平均分攤」，趨勢圖說明改為「依付款日期整理」
  （群組統計的趨勢圖本來就不能選時段，原本的「選取時段可同步篩選」提示也一併拿掉）。
- 個人統計「值得注意」：洞察帶上旅行出發日，旅行尚未出發時在標題下標「目前為行前支出」
  （以瀏覽器本地日期判斷；舊快取沒有出發日時不標）。
- 視覺密度先處理結算頁「每人統計」：原本每位成員一張內層卡片＋三列明細，改為分隔線列表，
  左側名字與「已付款・應分攤」一行小字，右側放大顯示餘額與應付／應收。其他頁面的卡片精簡另案評估。
- 本機瀏覽器驗證：建立旅行按鈕文案、群組統計兩種口徑標示、未出發旅行的洞察標記（已出發旅行不標）、
  手機 390 結算頁無橫向捲動。
