## 1. 記帳視窗關閉時保護草稿

**改善前**：填入金額 100 和描述後按右上角 ×，視窗直接關閉。重新打開時內容已經不見，過程中沒有任何提醒。
旅行時常被聊天或付款打斷，這時要全部重填，挫折感很高。

**建議**

- 表單有修改時：
  - 關閉後暫存草稿，下次打開可以接著填。
  - 草稿功能還沒做之前，至少先跳出「繼續編輯／捨棄內容」確認。
- 空白表單照常直接關閉，不必每次詢問。
- × 按鈕、點遮罩、Esc、手機下滑關閉都算「關閉」，要一致處理。

**驗收**：填好金額和分帳後誤關視窗，內容不會在沒有提示的情況下消失。

**相關程式**：[ExpenseFormSheet.tsx](../src/components/trips/detail/expense-form/ExpenseFormSheet.tsx)、
[useExpenseForm.ts](../src/components/trips/detail/expense-form/useExpenseForm.ts)、
[expenseDraftStorage.ts](../src/lib/expenseDraftStorage.ts)

**已完成的做法**（2026-09-17）

- 新增模式：內容存在 localStorage，**每趟旅行各一份**（key 含 tripId），7 天後過期。
  關閉或切換旅行前立即寫入，成功後才顯示「草稿已保留」提示並離開；不必等待自動存檔。
  編輯途中也會自動存（debounce 0.5 秒），已成功寫入的內容可在重新整理後還原。
- 本機儲存空間不足或無法使用時，保留表單並顯示「草稿存不下來」，不顯示保存成功提示。
  選「繼續編輯」保留目前輸入；選「關閉並放棄內容」才執行原本的關閉或切換旅行動作。
- 下次打開同一趟旅行的記帳表單會帶回草稿，頂端明講「已帶回上次未填完的內容」並提供「捨棄草稿」。
- 編輯既有支出：草稿不落地（避免和伺服器上的支出不同步），改過才在關閉前問
  「繼續編輯／捨棄修改」；沒改過則直接關閉。
- ×、遮罩、Esc、footer 的「取消」與「切換旅行」共用離開前的草稿保護流程。
- 送出成功後清掉草稿；成員名單變動時草稿的分帳狀態會對齊目前成員。
- 離線草稿修補（`ExpenseDraftRecovery`）沿用既有流程，不另外存本機草稿。

**驗證紀錄**（2026-09-17）

- 相關 6 個測試檔共 38 項測試通過，涵蓋草稿還原、捨棄、編輯關閉確認、立即切換旅行與儲存失敗提示。
- 另以臨時測試確認：切換旅行立即卸載表單後草稿仍在；儲存失敗時可繼續編輯，或確認後才切換旅行。
- TypeScript 與修改程式檔案的 ESLint 檢查通過。既有測試仍有 React `act(...)` 警告；未做實機手勢驗證。

## 2. 地圖底圖出現「API KEY REQUIRED」

**改善前**：地圖上反覆出現「API KEY REQUIRED」浮水印。這對完成度的影響比配色或間距都大。

原本底圖使用 CARTO basemaps，程式裡沒有設定任何金鑰：

- 亮色：`basemaps.cartocdn.com/light_all`
- 暗色：`basemaps.cartocdn.com/dark_all`
- 設定位置：[TripMapCanvas.tsx](../src/components/map/TripMapCanvas.tsx)

當時單看畫面無法確定浮水印原因。另外 [sw.ts](../src/sw.ts) 原本只快取
OSM 圖磚，和實際使用的 CARTO 來源不一致。

**原始建議**

- 確認 CARTO 的授權條款與正式網域的用量限制。必要時改用需要金鑰的服務（例如 MapTiler 或 Stadia），
  或自架圖磚。
- 圖磚載入失敗時，改用替代底圖或中性的背景，不要把服務商的錯誤畫面直接顯示給使用者。
- 更換圖磚來源時，同步更新 SW 快取規則和 attribution。若金鑰要放在前端，需要調整 CLAUDE.md 裡
  「唯一的 `NEXT_PUBLIC_`」規則，或改由伺服器代理圖磚。

**驗收**：正式網域的亮色和暗色地圖都看不到浮水印；圖磚來源失效時，畫面仍然可以使用。

**已完成的做法**（2026-09-17）

- 先直接抓圖磚確認原因：`a.basemaps.cartocdn.com/light_all` 與 `dark_all` 不論有沒有 Referer
  都回同一張壓了「API KEY REQUIRED」浮水印的圖。此結果支持更換來源；
  單次抽查不足以判定 CARTO 對所有網域或流量的限制政策。
- 改用同樣免金鑰、色調同樣淡的 **Esri Gray Canvas**（亮色／暗色各一組），地名是獨立的標註層，
  和底圖一起疊上去。前端仍然沒有任何金鑰，CLAUDE.md 的「唯一的 `NEXT_PUBLIC_`」規則不用改。
- 圖磚來源集中在 [basemaps.ts](../src/components/map/basemaps.ts)：主要來源累積 6 張圖磚載入失敗
  才換備援（OSM 標準圖磚，深色主題以 CSS 調暗），失敗的圖磚用透明圖蓋掉，
  地圖容器本身是中性底色，不會出現破圖或服務商的錯誤畫面。
- attribution 跟著來源換；[sw.ts](../src/sw.ts) 的圖磚快取改成涵蓋實際使用的兩個網域
  （`services.arcgisonline.com` 與 OSM），並加測試防止之後來源和快取規則再度不同步。
- 圖磚以 `crossOrigin="anonymous"` 載入（兩個來源都回 `Access-Control-Allow-Origin: *`），
  讓正常回應以 CORS 方式供 SW 快取；快取策略另外允許 `0`（opaque）與 `200` 狀態碼。
  底圖和地名層都納入故障判斷，地名服務單獨失效時一樣會換備援，不會卡在沒有地名的底圖。

**驗證紀錄**（2026-09-17）

- 新增 7 項測試：來源不含 CARTO／金鑰、備援與深色處理、SW 快取網域與來源同步，
  以及圖磚層的 CORS 設定、底圖或地名層各自持續失敗都會換備援、偶發失敗不換。
- 實作階段紀錄：全套測試 1562 項通過；TypeScript、ESLint、Prettier、`pnpm build` 皆通過，
  並確認建置產出的 `public/sw.js` 含新的圖磚快取網域。
- 本次覆核：5 個地圖測試檔共 25 項通過，TypeScript 與變更檔案 ESLint 通過。
- 另外以臨時測試直接載入 SW 設定，確認快取策略接受 `0／200`、拒絕 `404／500`，
  共 4 項通過；臨時測試已移除。
- 抽查亮／暗底圖皆無浮水印；亮／暗底圖及地名層、OSM 備援共 5 個圖磚端點
  皆回應 `200` 與 `Access-Control-Allow-Origin: *`。
- 未做的驗證：正式網域實際開圖、真實離線時的圖磚快取命中、備援來源在真實斷線時的切換。

## 4. 在旅行內按「記一筆」直接帶入目前旅行

**改善前**

- 在澎湖旅行中按頂端的「記一筆」，仍會先問「這筆記在哪趟旅行？」。
- 從支出頁按新增，則會直接打開表單。
- 同一件事有兩種行為，而且這是使用頻率很高的操作。

**建議**

- 在旅行內（`/trips/[id]/*`）：直接帶入目前的旅行，表單內保留「切換旅行」。
- 在首頁、個人統計、地圖：才需要先選旅行。

**相關程式**：[GlobalQuickAddFlow.tsx](../src/components/layout/GlobalQuickAddFlow.tsx)（`pickTrip` 步驟）

**驗收**：在任何旅行分頁按頂端「記一筆」，第一個畫面就是這趟旅行的記帳表單。

**已完成的做法**（2026-09-17）

- [AppShell](../src/components/layout/AppShell.tsx) 開啟「記一筆」時，從路徑（`/trips/[id]/*`）讀出目前旅行並在開啟當下記住；
  桌機頂列與手機底部分頁列走同一個入口。
- [quickAdd.ts](../src/lib/quickAdd.ts) 的 `decideQuickAddTrip` 多收一個目前旅行：
  它在「我的旅行」清單中（id 或 hash code 都認）就直接開這趟的表單，
  已封存的也一樣（旅行內原本就能記帳）；切換旅行清單保留全部候選，目前這趟排第一。
- 目前旅行不在我的清單中（例如不是成員）時，退回原本的規則。首頁、統計、地圖與 PWA `/quick-add` 行為不變。
