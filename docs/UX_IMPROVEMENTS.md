## 1. 最優先：同一趟旅行的金額要能對得上

成都重慶該趟觀察到的畫面數字：

| 位置 | 顯示 |
| --- | --- |
| 頂端預算列 | 我的支出 NT$0、剩餘 NT$50,000 |
| 結算頁 | 總付款 NT$3,944、總應付 NT$1,972 |
| 個人統計 | 成都重慶支出 $1,972 |

統一為三個概念：

- **我的花費**：實際應分攤的部分，用來扣預算。
- **我已付款**：先代墊付出去的錢。
- **待收／待付**：與旅伴尚未結清的金額。

### 已完成（2026-09-16）

- 三處金額口徑查證：預算列 `total_spent`、結算 `totalOwed`、個人統計 `totalAmount`
  都是「每筆支出分攤給本人的 `splits.shareAmount` 加總」，定義本來就一致，不是不同口徑。
- 命名統一：預算列改稱「我的花費」；結算頁「總付款／總應付」改為「已付款／應分攤」，
  自己的摘要列改為「我已付款／我的花費」。
- 金額格式統一：統計、單趟統計、結算方案原本各自用 `Intl.NumberFormat`（`$1,972`）或
  手拼 `TWD 1972.00`，改為全部走 `formatCurrency`（`NT$1,972`）。
- 預算列加上口徑提示：只計入分攤給本人的金額，代墊他人的部分在結算頁。
- 預算列的分攤加總改以字串比對 `splits.user`，與結算、個人統計的 `.toString()` 比對一致
  （原本用 ObjectId 相等，型別不一致的舊資料只有這裡會漏算而顯示 0）。
- 金額精度統一：各頁不再先取整再加總，尾差以最大餘數法分配（見上方〈待確認〉的驗收紀錄）。

### 待確認

- **舊金額 migration（待實作）**：建立冪等 migrate-mongo `up` / `down`，將支出金額與
  `splits.shareAmount` 收斂到分並按同一規則分配小額尾差。備份實際修改的原值，回復時避免
  覆蓋遷移後的使用者編輯；大額不平衡、缺成員及原幣乘積異常另列清單，不自動重分。
  驗收須包含重跑不再變動、可回復、六組既有跨頁案例一致，以及遷移前後查詢成本比較。
  完成各環境 `pnpm migrate:up` 後，移除 `tripShellRead` 與統計聚合熱路徑每筆最大餘數法重算，
  將檢查留在寫入／異常資料防線；目前仍有讀取端成本，此項尚未完成。
- **編輯回存確認**：DTO 保留原幣與匯率但正規化 TWD 分攤，編輯表單會再反算原幣並取小數位；
  須用外幣非均分與 JPY 案例驗證開啟後原封儲存，不因反算精度而阻擋或改變分攤。
  明細目前並排顯示原幣、取到分的 TWD 與匯率，正式瀏覽器視覺驗收仍待完成。

## 2. 記帳表單可以更快，尤其是改分帳時

現況：先看到「快速記帳」與 AI 說明才到金額；付款人與分帳雖有摘要，展開後卻與日期、行程日、標籤、匯率混在同一區。
實際情境「這餐只有兩個人吃」，需要進入很長的詳細資訊區才能修改。

建議的欄位順序：

| 順序 | 內容 |
| --- | --- |
| 最上方 | 旅行名稱，可切換 |
| 主要輸入 | 金額＋幣別、描述、分類 |
| 直接可改 | 我付款／今天／全員均分 |
| 次要入口 | 一句話記帳、掃描收據 |
| 更多設定 | 匯率、標籤、關聯行程日 |

另外：從首頁選完旅行後，表單標題只有「新增支出」，建議持續顯示正在記哪一趟，降低記錯帳本的機會。
既有的「金額自動取得焦點」值得保留。

## 3. 行程頁的第一屏應更快看到行程

現況上方依序為：全站導覽 → 旅行標題 → 兩層分頁 → 預算列 → 行前提醒 → 旅行資訊 → 工具列；
桌面畫面上第一個活動已接近畫面底部。「還有 0 項待辦」占了明顯區塊但幫助有限。

建議：

- 目的地、日期合併到旅行標題附近。
- 行前提示縮成一列，例如「10 天後出發 · 清單已完成」。
- 加入固定的日期切換（Day 1、Day 2…），避免往下找。
- 旅行途中優先顯示今天與下一個活動。
- 每筆活動的編輯、移除收進「⋯」。

總評：目前視覺較像在「管理行程資料」，調整後會更像旅行當下查看的工具。

## 4. 統計的位置與尋找路徑不一致

單趟旅行的「群組統計」目前在「結算」底下，但想知道「交通花多少、哪天最貴」通常會先點支出。
建議保留現有主要分頁，只調整第二層：

| 主要分頁 | 第二層 |
| --- | --- |
| 行程 | 每日行程、隨手記、清單 |
| 支出 | 支出明細、花費分析 |
| 相簿 | 維持現有功能 |
| 結算 | 待收／待付、還款紀錄 |

個人統計則繼續負責跨旅行比較，兩者分工更直覺。

## 5. 結算畫面：按鈕依身分改字

「你應收 NT$1,972」的大摘要與付款人→收款人方向都清楚；但身為收款人時按鈕仍寫「標記已付」，語意需要停頓判斷。

- 我是收款人：**確認已收到**
- 我是付款人：**我已付款**
- ~~「總應付」改成「應分攤」~~、~~金額格式統一~~：已於第 1 項一併處理。

## 6. 首頁應呈現「這趟現在怎樣了」

旅行卡片目前只有名稱、目的地、日期、人數；可辨識帳本但看不出狀態。
另外，兩趟尚未出發的旅行都放在「進行中」，語意偏差。

建議：

- 分頁改為「目前旅行／已封存」，卡片標示「即將出發、旅行中、待結算」。
- 卡片加上「我的花費／預算」小摘要。
- 最近即將出發或正在旅行的那趟優先排序。
- 卡片直接提供「記一筆」與「查看行程」。

這比單純加大封面圖片更能提升首頁實用性。

## 7. 零星小項（容易修、也有感）

- 建立旅行的展開按鈕寫「加入日期、描述與旅伴」，展開後只有描述與日期；文案應與實際內容一致。
- 群組統計的「每日花費」按關聯行程日整理，趨勢圖則用付款日期；建議明確標示「依行程日／依付款日」。
- 個人統計對尚未出發、只有 3 筆支出的旅行已顯示「交通占 87%」等洞察；建議補「目前為行前支出」。
- 保留青綠主色，但減少卡片包卡片與說明文字，讓金額、活動名稱與主要按鈕更突出。
