# S 分階段完成紀錄

## 第一階段：先保存，再確認

新增獨立、依登入身分隔離的 IndexedDB 支出寄送紀錄。表單等待本機交易完成才關閉並顯示
「已暫存」，儲存失敗則保留表單且不送出請求。每次送出與補送前都確認紀錄已保存。

一般查詢快取仍可到期或更新格式；待送／失敗紀錄沒有 TTL，不跟著清除。舊版佇列在還原時
匯入獨立紀錄。完成狀態保留以阻止舊快取重新排入已完成的工作；伺服器仍以相同識別碼去重。
IndexedDB 的原子更新避免同身分多分頁新增不同支出互相覆寫。

明確失敗先保存輸入與錯誤，再移除暫存支出並復原摘要；下一階段提供草稿操作介面。
登出清除寄送紀錄，停止尚未寫入的查詢快取節流工作，避免清除後被舊 timer 寫回。

驗證涵蓋本機寫入等待／失敗、無查詢快取的立即重載、快取到期／格式不相容／損壞、
舊版佇列、重複離線重載與恢復補送。這一階段使用 IndexedDB 替身；真實瀏覽器驗證於後續階段執行。

本文件記錄分階段交付；S 尚未結案。各階段 commit，最終交付依 AGENTS.md 統一升版一次。

## 第二階段：草稿復原與離線讀取

全域顯示待同步／需修正的支出，可查看原因與匯出完整輸入；明確失敗後可載入既有記帳表單
修正後重送，或經確認捨棄。重送以一筆 IndexedDB transaction 保存新請求並退休舊草稿；
儲存失敗不移除原稿，重複提交同一份舊稿會被拒絕。尚不確定伺服器是否接受的 pending 工作
只允許查看與匯出，不提供可能另建重複支出的編輯操作。

已保存的登入者資料與其他表單依賴一起使用依身分隔離的快取，讓離線重載後仍能開啟表單。
離線查詢暫停網路請求；讀取提示區分已保存資料與本機未保存資料，恢復連線後繼續載入。
支出列表合併尚未完成的 mutation，背景重新查詢不會遮掉待同步列。

測試：永久失敗／重載／草稿替換交易與儲存失敗、舊稿重複提交、登出清除、完整欄位預填，
以及離線有／無快取提示、既有表單／查詢錯誤流程。共 59 項相關測試通過，TypeScript 與變更檔案 ESLint 通過。
