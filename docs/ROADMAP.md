## 待辦

### 11b. 🔹 第三方登入 (OAuth) — M〔頭像已完成，OAuth 待做〕
**為什麼**：降低註冊摩擦。
**做法**：Google 登入可用 Auth.js 或自建，與現有自製 JWT 並存。

### 12. 🔹 常用旅伴 (Travel companions) — S
**為什麼**：常和同一群人出遊，每次重加很煩。
**做法**：`User.companions: [userId]`，建旅程時一鍵帶入；也能快速複製上一趟的成員名單。

### 14. 🔹 PDF 行程 / 結算報告 (PDF reports) — M
**為什麼**：目前只有 CSV。一份漂亮的「旅程結算單 / 行程手冊」PDF 很適合分享與報帳。
**做法**：既有 [src/lib/exporters/](../src/lib/exporters/) 已抽象化，新增 PDF exporter（`@react-pdf/renderer` 或伺服端 puppeteer）。

### 16. 🔹 地圖強化 (Map enhancements) — S~M〔🟡 統計儀表板已完成，相片釘點待做〕
**為什麼**：地圖已有三模式 + 按天花費熱點權重，但缺彙總洞察與相片情境。
**已完成**：地圖疊統計儀表板（造訪 N 國 M 城 + 航段**里程加總**，`MapStatsBar` + `stats.ts`）與國家點亮 choropleth，私有 / 公開兩視圖皆有（commit `bba75fb`）。
**待做**：（連動 #4）相片釘點——把支出收據附件（R2）依所在地點釘上地圖、點擊看照片。屬跨功能整合（座標關聯 + 私有 presigned GET），非純前端聚合，成本 M。可選延伸：更深的統計洞察（各國/城市造訪次數排行、每趟里程排行）。

### 進階深化（已完成功能的延伸）
- **#1 預算**：每日步調、每人預算。
- **#3 分帳**：逐項分帳（item-level split）。

## 建議落地順序

```
隨手可做（S，穿插填空）
  └── 12 旅伴

中等（M）
  ├── 16 地圖相片釘點（統計儀表板已完成，剩相片釘點，連動 #4）
  ├── 14 PDF 報告
  └── 11b OAuth 登入
```

**新功能慣例**：DB 存取走 Mongoose + `dbConnect()`，業務邏輯走 server actions 回傳 `ActionResult<T>`，新使用者字串**四語系都要補**，新識別碼沿用 `hashCode` 格式（見 [hashcode.ts](../src/lib/hashcode.ts)）。實作前各項仍需獨立設計（schema 遷移、i18n、測試），再逐項開票動工。
