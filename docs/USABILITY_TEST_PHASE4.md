# Phase 4 可用性測試套件

> 狀態：🟡 腳本與模板已備妥，尚未招募／執行
> 建議人數：5–7 人
> 單場時間：35–45 分鐘
> 測試目的：驗證 Phase 2–3 的首次成功、快速記帳、導覽、錯帳修正、離線與邀請流程

沒有真實受測者紀錄前，本文件不是「測試已完成」報告。完成每場後填寫匿名觀察表，全部結束再填總結與決策。

## 1. 受測者條件

- 過去一年曾與朋友或家人安排旅行。
- 曾用 Splitwise、試算表、聊天群或筆記記錄共同費用。
- 5–7 人中至少 3 人主要用手機、至少 1 人平時使用鍵盤操作網頁。
- 不招募本功能的直接開發者；避免只找熟悉資訊架構的人。

只記匿名編號（P01–P07）、裝置類型與相關經驗區間，不記真名、帳號、旅行名稱、支出描述、邀請碼或真實金額。

## 2. 測試環境

- 使用專用測試帳號與虛構資料。
- 預先準備一趟三人成員旅行、JPY／TWD 幣別、兩天行程與一個有效邀請連結。
- 手機以 360–430px viewport 為主；桌機至少測一次鍵盤-only。
- 離線任務使用瀏覽器 Network Offline，完成後恢復 Online。
- 錄影／錄音需事前取得同意；不同意時只做匿名筆記。

## 3. 主持開場

> 我們測試的是產品，不是你。過程中請說出你正在找什麼、期待按下後發生什麼。遇到困難可以停下來，但我不會直接提示按鈕位置。所有資料都是虛構測試資料。

先問兩題背景：

1. 上次多人旅行如何記帳與結算？
2. 旅途中最怕記帳工具發生什麼問題？

## 4. 任務

| # | 給受測者的任務 | 成功條件 | 主要觀察 |
| --- | --- | --- | --- |
| 1 | 建立一趟三人日本旅行，並邀請同行者 | 建立後進旅行；完成邀請動作 | 是否理解空狀態、漸進欄位與下一步 |
| 2 | 剛付了 JPY 6,000 晚餐，請記下並三人均分 | 正確旅行、幣別、金額、付款人與 3 人分攤 | 開表時間、旅行誤選、送出前核對 |
| 3 | 發現其中一人沒吃，請修正上一筆 | 改成 2 人分攤並成功保存 | 能否找到支出、理解展開與編輯 |
| 4 | 找出你目前該付誰，並記錄部分還款 | 找到結算方案並完成還款 | 「我的」與旅行結算是否混淆 |
| 5 | 在離線狀態新增交通費，恢復網路後確認 | 看見待同步，恢復後資料存在 | 是否信任狀態、會不會重複送出 |
| 6 | 使用這個完整邀請連結加入旅行 | 看懂預覽、登入／註冊後返回、加入後進旅行 | 是否理解訪客與加入的差異 |
| 7 | 回到旅行首頁，說出今天下一個行程與今日花費 | 從情境首頁找到兩項資訊 | 行前／旅中／旅後資訊優先級 |

主持人只有在受測者宣告放棄或 3 分鐘沒有進展時才能給一級提示；記下提示內容與發生時間。

## 6. 嚴重度與決策規則

| 嚴重度 | 定義 | 處理 |
| --- | --- | --- |
| S1 阻斷 | 無法完成、資料錯誤／遺失、金額或分攤錯誤 | 發版前修正 |
| S2 重大 | 多數人需提示、明顯誤選旅行或重複送出 | 下一個修正批次優先 |
| S3 摩擦 | 可完成但回頭、猶豫或命名不清 | 與事件數據一起排序 |
| S4 偏好 | 純視覺或個人偏好，不影響理解 | 記錄，不立即改 |

只有符合以下任一條件才重排全域導覽：

- 5–7 人中至少 3 人找不到同一入口，或
- `navigation_used` 顯示穩定的繞路模式，且與訪談觀察一致。

不要只因一位受測者的偏好移動「記一筆」、統計或地圖。
