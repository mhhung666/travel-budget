## 阻擋缺陷：離線重載遺失待同步支出

重現步驟：

1. 線上開啟測試旅程與記帳表單，填入合成支出。
2. 將瀏覽器切為離線，送出後顯示「已暫存支出」與「待同步」。
3. 等待超過持久化節流時間；直接讀取 IndexedDB，確認 1 筆 `expenses/create` 工作為 pending、isPaused=true，且有 1 筆 optimistic 支出。
4. 保持離線並重載頁面，捕捉到 action 請求 `net::ERR_INTERNET_DISCONNECTED`。
5. 約 5 秒後 IndexedDB 暫停工作為空，optimistic 支出為 0；畫面只剩既有支出，摘要一度仍包含未同步金額。
6. 恢復連線並重載，遺失支出沒有補送。NT$3 與 NT$4 兩筆測試均重現；正式 API 只查到線上支出與不重載直接補送的支出。

**驗收當時的程式檢查推論**：TanStack onlineManager 初值為 true；目前
[QueryProvider](../src/components/providers/QueryProvider.tsx) 未在恢復暫存前同步瀏覽器的初始離線狀態，
持久化還原完成即呼叫 resumePausedMutations。補送失敗走
[offlineMutations](../src/lib/offlineMutations.ts) 的 onError 清除 optimistic 列；失敗工作不再是 paused，
下次持久化不保留。既有測試手動設定 onlineManager，未覆蓋真正離線啟動的初值。

完成條件：離線啟動時保留待同步工作與草稿，不因暫時 transport failure 丟棄；
重複離線重載後恢復連線仍可補送，列表與摘要一致，並新增涵蓋瀏覽器初始離線狀態的回歸驗證。
由 [改善建議 S](./IMPROVEMENTS.md) 追蹤，不能以本次發現代替修復。

後續本機修正：QueryProvider 已在建立 QueryClient 前同步瀏覽器初始連線狀態。
新增整合回歸涵蓋兩次離線重新掛載、JSON 持久化、列表與摘要保留，以及連線事件後只補送一次。
測試使用記憶體替代 IndexedDB，尚未重跑正式瀏覽器／SW 驗收，不改動上方正式站未通過的結論；
也不代表已處理請求送出後斷線或回應遺失。

後續 2026-09-13：S 已完成送出前獨立保存、永久錯誤草稿復原、離線讀取提示及
本機 production build 的真實 Chrome／IndexedDB／SW 六項驗收，包含多分頁、回應遺失及儲存失敗。
結果與重跑方式見 [S 分階段完成紀錄](./OFFLINE_EXPENSE_COMPLETION.md)。尚未部署，

## 正式站支出頁的小樣本效能

「202609 澎湖」空支出頁；每種寬度 3 組 fresh context → 同 context reload，共 12 次。
使用同一登入身分，cold context 無 HTTP／IndexedDB／SW 快取；warm 保留快取。
沒有套用 network routing、網路節流或 CPU 降速；手機組只有 viewport 寬度差異。
各次內容就緒後等待 1.5 秒，記錄頁面 CDP loadingFinished 與 Resource Timing 的彙總，不保存私人 response body。

| 寬度 | 快取 | 內容就緒中位數（範圍），ms | 頁面觀測 encoded bytes 中位數 | JS transfer 中位數，bytes |
| --- | --- | --- | --- | --- |
| 1440px | cold | 9,320（5,592～10,008） | 534,241 | 366,138 |
| 1440px | warm | 2,298（2,000～2,340） | 402 | 0 |
| 390px | cold | 5,623（5,288～5,654） | 530,776 | 366,138 |
| 390px | warm | 2,076（1,886～2,199） | 210 | 0 |

就緒條件為「新增第一筆支出」按鈕可見，並非 TTI／INP／LCP。
觀測時 12 次均由 SW 控制；bytes 不包含所有 worker 預快取，也不包含觀測結束後才完成的請求，
不能解讀成全站總流量。每格只有 3 筆，無前版本控制組，不報 p95 或改善幅度。
冷載入有約 5～10 秒等待，尚無 server trace 能歸因到 Vercel、Atlas 或前端請求鏈。
