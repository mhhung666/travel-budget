# Web 與 Mobile 產品設計規格

Travel Budget 的 Web（含窄版瀏覽器、PWA）與 Mobile（iOS／Android 原生 App）使用同一份旅行帳本。以下按使用者任務列出目前程式提供的能力。Expo 的瀏覽器匯出只供預覽；表中的 Web 指 Next.js 網站。

## 兩端功能對照

| 使用者任務         | Web／PWA                                                                                | Mobile                                                                                                               |
| ------------------ | --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 登入與管理帳號     | 註冊、密碼登入／重設、修改密碼、驗證新 Email、頭像、好友                                | 使用同一帳號；「我的」提供本人資料、頭像、密碼、Email、好友及偏好                                                    |
| 找到旅行、快速記帳 | 卡片主區開行程；更多可複製邀請。全域「記一筆」可選旅行                                  | 卡片主區開概覽；旅行內分享邀請。全域「記一筆」支援選旅行、保存原旅行草稿再切換                                       |
| 建立旅行與管理成員 | 建立／加入、個人封存、邀請、虛擬成員認領、角色及旅行管理                                | 建立／加入、個人封存、成員與角色管理。管理員可分享認領連結，受邀者在 Web 完成認領                                    |
| 閱讀與維護行程     | 行程是旅行主入口。成員閱讀、管理員維護日與活動。另有 Markdown、票券、行程匯出及公開閱讀 | 旅行內有獨立行程分頁。成員閱讀、管理員維護日與活動。日說明呈現 Markdown 原文，可看成員訂位碼，票券附件與匯出留在 Web |
| 輸入支出與分帳     | 多幣別、四種分攤、收據、標籤、留言與行程日關聯                                          | 多幣別、四種分攤、明細與私人收據讀寫。基本編輯保留原帳；重新分攤須預覽並確認。從活動記帳待排期                       |

| AI 輸入            | 管理員匯入行程文字，成員從文字或收據取得支出草稿，檢視後確認                            | 原生 AI 入口未排程                                                                                                   |

## 共用的產品規則

- **帳本與匯率。** 每趟旅行在建立時選定基準幣別；舊資料缺欄位採 TWD。原幣與完整匯率分開保存，每單位原幣換得多少基準幣即為匯率。同幣匯率為 1。基準金額記到分，含 JPY；「我的分攤」與代墊金額分開，還款只改結算餘額。[帳本規則](../../apps/web/docs/MOBILE_API.md#b1-基準幣別契約)
- **分攤。** 均分、固定金額、百分比、份數均沿用後端計算。到分尾差依穩定順序分配，份額加總等於支出。例：100 元均分三人為 33.34、33.33、33.33。已有歷史份額、缺少原分攤模式的支出，基本編輯保留份額。[進階分攤](../../apps/mobile/docs/BACKEND_CONTRACT.md#g3a-2-進階分攤新增與編輯)
- **行程日與活動。** 旅行及支出的日期是當地日曆日，日號可跳號。活動屬於開始日；只有明確的正日差才投影到已建立的後續日卡。延續提示不重複計數或匯出。支出可關聯行程日，刪活動會保留帳務。[跨日規格](ITINERARY_PRESENTATION.md)
- **身分與可見範圍。** 以成員 ID 辨識本人、付款人與分攤對象。個人封存只整理本人列表。個人預算、收據與活動訂位碼僅在各自授權範圍讀取。公開分享經獨立資料介面輸出；好友關係本身不授予旅行權限。[分享範圍](../../apps/web/docs/FEATURES.md#分享)
- **確認與恢復。** 草稿可以修改。採用操作收據的流程在確認後固定請求 UUID 與內容；若回應遺失，查原操作並依該流程的規則恢復。已成功寫入、只有畫面刷新失敗時，只重讀。Web 個人封存與 App 個人封存的恢復方式不同。[封存互動](MY_TRIPS.md#互動與恢復) · [App 本機持久化](../../apps/mobile/src/storage/README.md)

## 介面與互動

同一任務對齊用語、資訊順序、可見資料、確認結果與錯誤狀態。版面依可用寬度、輸入方式及輔助技術調整。

| 設計決定           | 共用要求                                                                                   | 平台落點                                                                                                                                                                                         |
| ------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 導覽               | 同一操作只觸發一次；閱讀、更多、寫入入口可分辨                                             | Web 旅行分頁為行程／支出／相簿／結算；App 為行程／概覽／支出／結算。列表主入口依上表                                                                                                             |
| 表單與破壞性操作   | 指明作用對象與影響；取消不寫入。結果未知保留恢復入口                                       | Web 支援鍵盤、Esc 與回焦；App 處理返回／側滑、軟鍵盤與安全區。多選刪除的返回規則見專規                                                                                                           |
| 字級、外觀與操作區 | 四語（繁中、簡中、英文、日文）、深／淺色；長名稱、金額與大字級能換行，狀態有文字與讀屏名稱 | Web 使用 [CSS 與語意色](../../apps/web/src/app/globals.css)，App 使用 [原生 tokens](../../apps/mobile/src/theme/tokens.ts)。旅行卡操作區至少 48、行程操作區至少 44，各依功能規格的邏輯單位與斷點 |
| 載入與更新         | 區分首次載入、空資料、背景更新、拒絕存取及結果未知。未知數量或金額不顯示成零               | Web 可用既有快取；App 私人帳務查詢限本次記憶體。已知撤權後須遮蔽私人內容                                                                                                                         |
