## 共同 UI／UX 設計

### 設計重點

讓使用者先為旅行命名，再決定整本帳用什麼幣別計算。基準幣別是一個已有預設值的表單欄位，不是一組要求逐一比較的動作按鈕。維持「查看目前值 → 開啟搜尋 → 選取 → 回到表單 → 建立旅行」的單一路徑。

Web 已將代碼＋名稱欄位放在旅行名稱下方，支援搜尋單選；App 仍在名稱之前鋪開搜尋與 Chip，待 BC2 接入。本次兩端統一欄位位置、文字、候選順序與選取結果；彈出容器依螢幕適配。以下依原始碼盤點與設計推導，沒有宣稱已操作實機或完成可用性測試。

### 建立表單線框

```text
建立旅行                                    關閉／返回

旅行名稱
┌──────────────────────────────────────────────────┐
│ 例如：京都秋日旅行                               │
└──────────────────────────────────────────────────┘

帳本基準幣別
┌──────────────────────────────────────────────────┐
│ TWD · 新臺幣                                   ⌄ │
└──────────────────────────────────────────────────┘
此旅行的總額、分帳與結算以此幣別計算，
建立後無法更改。

其餘既有旅行欄位……

                                      [建立旅行]
```

- 名稱、幣別為單欄排列，桌面也不左右拆開；幣別不藏進進階設定。其餘欄位維持各端既有能力，不為排版新增 App 目的地搜尋或好友功能。
- 關閉的幣別欄位採中性輸入框外觀，整列可點、右側向下箭頭；不使用實心品牌色、加號或一排幣別 Chip。欄位永遠顯示代碼及名稱，長名稱換行，不縮字或只剩符號。
- 說明直接放欄位下，正常正文色階；「建立後無法更改」可加字重，不能只藏在 tooltip。屬固定規則，預設不用紅色警告，也不要求額外勾選。
- 表單唯一高強度主操作是「建立旅行」。取消／返回沿用平台位置；打開幣別面板時，背景表單及建立按鈕不可操作。

### 搜尋、排序與防誤選

- 空搜尋分「常用幣別／其他幣別」，不另做一排常用快捷按鈕。常用沿用 [Web 既有次序](../../apps/web/src/constants/currencies.ts)：`TWD, JPY, USD, EUR, HKD, THB, KRW, CNY, GBP, SGD, AUD, MYR, VND, PHP, IDR`，與後端允許集合取交集；其餘依代碼字母排序，各幣別只出現一次。兩端使用同一份案例核對次序，不依裝置 Intl 回傳順序。
- 輸入後合併成單一結果清單，不顯示空分組。精確代碼命中最前，接著代碼前綴，再來本地化／英文名稱命中；同級沿用上述次序。允許完整文字，取消 App 三字元限制與只限代碼的輸入方式。
- 名稱搜尋依目前介面語言及英文名稱；例如繁中可找 `美元`、`usd`、`US Dollar`。繁簡日文別名跨語系搜尋不列首輪保證。名稱產生失敗仍保留代碼候選，不讓 Intl 能力決定哪些幣別可選。
- 搜尋字串、鍵盤暫時指向的列、已選值是三種不同狀態。只有明確點列或 Enter 選取才更新值；方向鍵／hover 只改焦點，勾號只表示已選值。清除搜尋不清除已選值，也不自動選第一筆。
- 中文／日文輸入組字期間，Enter 只完成組字，不選幣別、不送表單。軟鍵盤搜尋鍵不建立旅行，也不自動採用第一個結果；Web 選取所用 Enter 不可穿透到表單 submit。
- 搜尋無結果顯示「找不到符合的幣別」與「試試代碼或名稱，例如 USD、美元」，提供「清除搜尋」。不提供「新增幣別」，原值仍保留；取消可直接回表單。
- 選取同一值照常關閉但不產生未儲存變更；重開清空搜尋並定位已選項。若目前值已失效，保留欄位錯誤並從可用清單頂部開始，不畫假勾選。

### 視覺與無障礙

沿用 [共同設計尺度](MY_TRIPS.md#版面尺度)：語意色、品牌綠、間距 4／8／12／16／24、控制項圓角 12；欄位高至少 52、選項列至少 48 邏輯單位，長名稱與大字級時增高。正文／選項 16、輔助說明 14；選取列用淡底色加勾號，焦點另有輪廓，非選取項不框成一顆顆按鈕。

Web 使用可及的單選搜尋模式（combobox／listbox／option 與 selected 狀態），欄位連結標題、說明及錯誤；App 讀出「帳本基準幣別、TWD、新臺幣」及列的已選狀態。可用實作依平台元件能力決定，不能只補 aria 標籤卻沒有鍵盤行為。關閉恢復焦點與表單捲動位置；鍵盤不能蓋住搜尋結果，點結果第一下即可選取，不只收起鍵盤。

深淺色保持對比，不以顏色單獨標示錯誤或選取。欄位下的不可更改說明全程可讀，不因只剩一個候選或開始搜尋就消失於原表單。

## 選單與產品規則

- 欄位放在旅行名稱之後、進階欄位之外，標題「帳本基準幣別」。初始值 `TWD · 新臺幣`；不依目的地、系統語言或參考匯率自動更換。
- 常駐說明：「此旅行的總額、分帳與結算以此幣別計算，建立後無法更改。」不另加一層確認對話框。
- 關閉時只顯示已選代碼＋本地化名稱；展開後頂部輸入搜尋，下方是單選清單，已選項有勾選狀態。外觀、平台容器及狀態依上方共同 UI／UX 規格，不沿用設定頁「加入常用幣別」的加號語意。
- 搜尋接受代碼、本地化名稱及英文名稱，例如 `usd`／`美元`／`US Dollar`；忽略大小寫及頭尾空白。不能以任意文字建立新幣別；輸入搜尋不改已選值，只有選取選項才更新。
- 無關鍵字時常用幣別優先、其餘按代碼排序；精確代碼命中優先。清單可捲動且所有允許項均可到達，不截斷成前 12 筆。搜尋無結果提供清除搜尋，不自動選第一筆。
- 選取即關閉，重開清空搜尋並定位已選項；取消／Esc／點外部關閉不改選值。Web 支援方向鍵、Enter 選取、Esc 關閉並返回觸發欄位；Enter 不得順便送出建立表單。
- 四語為繁中、簡中、英文、日文；名稱顯示失敗退回代碼。代碼永遠保留，不能只用 `$` 等符號辨識。
- 候選代碼以後端 `supportedBaseCurrencies` 為準；後端固定開放非 TWD 建立。客戶端仍保留舊 capabilities 回應的 TWD 守衛，供舊服務或快取相容。客戶端 Intl 只負責名稱，不能自行擴大／縮小後端允許清單。
- 初次能力載入／失敗時保留表單，顯示載入或重試並阻擋建立；重查期間不清除已選幣別。若最新能力不再允許已選值，提示重新選擇並阻擋送出，不默默改成 TWD。後端仍做最後驗證。
- 草稿保留、未儲存離開判斷與清空草稿包含已選基準；搜尋字串不是帳務欄位。送出中禁止修改。已確認的 UUID／body 不因能力更新或搜尋改變；結果不明仍循既有收據恢復，確定拒絕才允許修正後重新確認。
- 基準不同於支出原幣：建立後尚無常用設定時，以基準作為首次記帳預設；例如 USD 帳本仍可另設 JPY 原幣。基準匯率固定 1，其他幣別缺參考匯率時明示並讓使用者手動填寫，不捏造匯率。
- 保留 `moneyScale: 2` 與現有尾差規則，JPY 也不取整；本次不加入各國現金最小單位、三位小數帳本、舊帳本換基準或外幣離線自動送出。

### BC1a 已交付與整合方式

`lib/currencySelection.ts` 只按呼叫端候選去重、排序及搜尋，常用次序由現有 constants 唯一來源提供；常用名稱取四語文案，其餘與英文名稱使用 Intl，名稱失敗保留代碼。`CurrencySearchPanel` 使用受控 listbox，`value` 決定勾選、活動列只決定鍵盤焦點；清除／取消不改值，組字 Enter 不選取或 submit。`CurrencyPicker` 為受控 modal Popover 外殼，選取即關閉，取消／Esc／點外部關閉後回觸發欄位；設定 adapter 保留加號、排除已加入項及單次新增回呼。

### BC1c 已確認操作與恢復

建立後選配的好友邀請維持 best-effort，傳送失敗不將已建立旅行回報失敗；恢復不自動重播未 journal 化的好友邀請，必要時在成員設定補加。沒有新增帳務模型、API 欄位、journal 格式或正式 gate；尚未確認的建立草稿仍只留記憶體，不承諾重啟保存。

### 能力與確認狀態的實作判斷

- 建立按鈕與 submit handler 共用同一條守衛：線上、能力已成功確認、沒有重查／查詢失敗、選值在最新有效集合、選擇器未開啟、沒有進行中／原待確認操作。不能只停用按鈕而讓表單 Enter 繞過。名稱在能力讀取中仍可編輯。
- 重查保留上一份候選和選值，但暫停建立；失敗保留輸入並就近重試。最新集合移除目前值時顯示錯誤，仍允許打開清單明確改選；只剩 TWD 也不直接重設。正常已選 TWD 且僅有 TWD 時才採唯讀呈現。能力若不含任何有效候選，顯示不可建立與重試，不捏造 TWD 候選。
- Web `handleClose` 已計入單獨的基準修改；App 的 `dirty` 已納入單獨基準修改，搜尋／取消不算變更。Web 搜尋子視圖返回不設草稿旗標；清空草稿回 TWD 並清理搜尋／錯誤，但不得清除已確認 journal。
- Web `finally` 只結束送出狀態；BC1c 已依原 UUID 的持久化 `pending／done／rejected` 判斷是否解鎖，不憑 catch 的錯誤字串推斷未寫入。存檔失敗發生在確認前可以修正輸入；寫入結果未知或終局未能落盤都保持凍結，透過原恢復入口補查。查詢拒絕不能當成原寫入拒絕；終局狀態成功保存後才解除原確認。既有 journal 格式與固定 body 不變。
- 能力重查只限制**新確認**；已有持久化操作的查詢／原 UUID 恢復不依最新清單改 body 或停止查詢。換帳號／環境後不得顯示前一身分的確認或套用晚到結果，沿用帳號隔離與登入世代守衛。
