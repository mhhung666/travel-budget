# 我的旅行：Web／Mobile 共同設計

更新：2026-10-12。狀態：**UX-T1／UX-T2 已實作、已提交／未部署，工程檢查通過；UX-T3 裝置／使用者驗證待執行**。共同項目代號：**UX-T**。範圍為原生 App、窄螢幕 Web 與桌面 Web 的旅行列表，不歸屬 Mobile 單端路線。

## 設計判斷

「我的旅行」首先應讓人辨認旅行、知道自己的帳務狀態，再選擇進入或記帳。改造前尤其在 Mobile，建立、加入、切換列表及卡片操作連續使用相似的按鈕排列，旅行內容反而失去主角位置。改善方向是**用內容卡片承載旅行、用分頁切換範圍、用一個明確快捷操作處理帳務，把低頻管理收進選單**。

統一兩端的資訊順序、名稱、操作位置與結果；原生 sheet、Web 選單與響應式欄數各自適配。不新增封面圖、搜尋、統計總覽或功能入口來填滿版面，也不靠縮小觸控區減少按鈕感。

## 元件與防誤觸規格

### 頁首與分頁

- 頁名統一「我的旅行」；動作用「建立旅行」「加入旅行」。未封存分頁用「旅行」，不叫「目前／進行中」，因為其中包含已結束旅行。
- 「旅行／已封存」使用同一水平 tab 列，以底線、字重及選取語意辨認；不使用兩個獨立的大型實心按鈕。狀態 badge 則不可點，不能長得像 tab。
- 沿用沒有封存時可省略 tab 列的規則；若目前在已封存且還原最後一趟，保留所選 tab 與空狀態，不突然跳回一般列表。Web 目前依陣列長度移除 Tabs，實作時要補選取狀態。
- 數字只採完整、可信的授權計數；刷新或權限不明時可暫不顯示，不能用 App 已載入頁數冒充總數。
- 完全沒有旅行時，把唯一高強度「建立第一趟旅行」放空狀態，旁邊保留次要加入入口；頁首不重複這組操作。只有封存時則說「目前沒有未封存的旅行」，保留查看已封存。

### 旅行卡片

- 卡片是中性容器；名稱為第一視覺層，狀態為第二層，日期／地點／人數為低強度資訊，金額使用對齊數字。不將人數與每個數據都包成按鈕形膠囊。
- **主區、右上角更多、底部快捷是三個不重疊的互動區。** 主區含名稱與摘要，提供「開啟旅行 ›」提示；提示不是第四個重複按鈕。點空白外框不觸發導覽，點更多／記帳不穿透。
- Web 主區用真正的 Link，更多及快捷與它為同層元素，不能把 button 包在 Link 內，也不在外層容器攔截所有點擊。App 同樣使用兄弟 Pressable；輔助觸控範圍不能蓋到相鄰操作。
- 保留完整旅行名稱，允許折行；更多有固定獨立欄位，不蓋住標題。不得只靠 hover 或 tooltip 才能辨認同名旅行。移除 Web 主卡片描述段落，詳細描述留旅行內。
- 日期依既有 date-only 規則與語系格式；部分日期明示哪一端未設定，無日期顯示「尚未排定日期」。目的地缺值時省略，不放假地名。
- 兩端常駐「我的分攤」與「待收／待付／目前無待收付」兩項本人資訊；窄版可分行，金額不得截斷，幣別明確。Web 原有本人預算可作分攤下的輔助文字，Mobile 缺欄位時不畫空進度條、不逐卡補 API。
- 階段採「即將出發／旅行中／已結束／未排日期」，封存另外表達個人整理狀態。將階段與本人餘額分開，避免 Mobile 把 `myBalance = 0` 推論成全團已結清。Web 的「待結算／已結清」卡片 badge 首輪改為上述共同語意；結算頁原有業務判斷不變。
- 底部最多一個低強度、帶文字的快捷：未封存且已結束、本人餘額絕對值至少 0.01 時為「查看結算」；其他未封存為「記一筆」；封存無快捷。記帳／結算只開頁面或表單，不直接送出。
- 更多可用「⋯」，讀屏名稱須含旅行名，例如「京都秋日旅行，更多操作」。Web 選單、App 底部 sheet；字級過大可擴展成可捲動視窗。Web 既有複製邀請保留在選單，App 沿用旅行內分享，不因格式統一新增 API。

### 導覽與封存

「開啟旅行」在 Web 仍進行程、App 仍進概覽；這是既有產品差異，首輪不改目的頁，也不把兩端都標成「查看行程」。卡片下重複的 Web 行程按鈕移除，但鍵盤與滑鼠都能從主區完成導覽。

封存／取消封存先展開確認，寫清楚旅行名稱與「只整理你的列表，其他成員與帳務不受影響」。保留一般成員操作、不因餘額阻擋、不視為刪除或退出。Web 需補列表確認；App 沿用 `PersonalArchive` 的 review／sending／pending 流程，只換呈現，不另做直接寫入。

成功後移到正確列表並提示結果，焦點回相鄰卡片或分頁標題；失敗保留內容與重試，結果不明進既有恢復流程。不得為了 sheet 關閉就隱藏待確認狀態、換新 UUID 重送或丟棄本機草稿。取消確認沒有寫入。

### 視覺尺度

沿用品牌綠與各端語意色，不另創配色系統。頁面背景／卡片表面分層，少量邊框、低陰影；優先靠留白及字級建立階層，取消 Web 卡片 hover 位移。紅色只給錯誤或危險語意，待收／待付用文字辨認，不能只依紅綠。

| 項目 | 共同設計目標                                                               |
| ---- | -------------------------------------------------------------------------- |
| 間距 | 4／8／12／16／24／32 階梯；卡片內距 16，卡間 16，分組間 24–32              |
| 圓角 | 卡片 16、控制項 12；tab 採底線，避免每層都成圓角框                         |
| 字級 | 頁標題 24、卡片名稱 20、正文／金額 16、輔助文字 14；隨系統縮放             |
| 觸控 | 本案兩端可操作目標至少 48×48 邏輯單位，鄰接操作至少 8 間隔；文字樣式也適用 |
| 回饋 | 主區按下才有表面色；快捷與更多各自回饋；鍵盤焦點框清楚、不被裁切           |

數值是本案目標，Mobile 可映射現有 [tokens](../../apps/mobile/src/theme/tokens.ts)，Web 在本頁對應相同語意；不為本頁大幅改全站 tokens。保留深／淺色、減少動畫偏好與安全區。

## 共同交付順序與驗收

| 切片             | 兩端共同產出                                                               | 完成條件                                                                         |
| ---------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| UX-T1 資訊階層   | 頁首、分頁、卡片共同結構；Web 移除建立 FAB／重複行程按鈕，App 移除整列更多 | 同一組資料可並排對照；主要內容、動詞與位置一致；保留完整名稱、大字級及底部導覽   |
| UX-T2 互動與狀態 | 分離點擊區、鍵盤語意、App sheet／Web 選單、共同封存確認與焦點恢復          | 所有操作只導覽或送出一次；取消無寫入，失敗／未知結果仍可恢復；最後封存還原不跳頁 |
| UX-T3 驗證       | 四語／深淺色／手機／桌面／iPad 的對照與任務測試                            | 下列工程、裝置與使用者驗證完成後，才將設計標記為交付                             |

實作保留現有列表與 quick-add 排序、金額、權限、分頁及 UUID 恢復規則。共享的是本文件與行為案例，不把 React 元件或 Web source 塞進 contracts；首輪預期不需更動 API，若盤點出缺欄位再單獨評估相容契約。

驗收資料固定包括：零旅行、全封存、一般／封存各超過一頁、旅行中／即將出發／已結束／部分日期／無日期、長名稱／同名、零分攤零餘額、本人待收／待付、不同基準幣及離線／錯誤／未知結果。

- **防誤觸行為**：依序點卡片主區、快捷、更多與邊界；每次只產生目標操作，開更多不導覽、開記帳不提交、按取消不封存。跨卡片連續操作不沿用上一趟目標。
- **閱讀與無障礙**：320／390 CSS px、桌面約 1280px、iPhone／iPad 大字級；四語 `zh`／`zh-CN`／`en`／`jp` 與深淺色。名稱、金額、按鈕不遮蓋、不截斷；Tab／Enter、Esc 與 VoiceOver 可辨認主區、快捷和更多並返回合理焦點。Android 驗收需另列實際狀態，不以匯出取代。
- **任務驗證目標，非既有成果**：找至少 5 位未參與設計的使用者，用相同資料比較現況與提案，交替測試順序；完成「開指定旅行、記一筆、加入旅行、查看結算、封存再還原」。記錄首次點擊、誤入頁面、返回次數及是否需提示；每個任務至少 4/5 無提示完成，所有人都能區分建立旅行與記帳，零非預期提交。未達標時優先調整文案與熱區，不只換顏色。
- **工程檢查**：實作時跑受影響的導覽、卡片、分頁、封存／恢復行為測試與各 App 必要檢查；涉及 workspace／契約再依 [開發規範](../DEVELOPMENT.md) 執行完整驗證。本輪包含兩端介面與行為測試，工程結果見下段；裝置與使用者驗證另由他人執行。

## 實作結果與剩餘驗證

UX-T1／UX-T2：兩端頁首、水平底線分頁、完整名稱、日期／目的地／人數及兩項本人帳務已整理；卡片主區、更多、快捷分離，Web 移除建立 FAB／重複行程按鈕與 hover 位移，較寬畫面維持兩欄，App／iPad 保留單欄。空狀態只保留一組建立／加入；還原最後封存後停留原分頁。四語文案及幣別代碼明示，零餘額不推論全團結清。

封存：Web 選單先確認旅行名稱與本人範圍，取消零寫入，送出防重複、失敗留原確認供手動重試；沿用既有封存／還原絕對狀態 mutation，沒有另加 journal／UUID。App 底部可捲動視窗沿用 `PersonalArchive` 原 review／sending／pending 及 E 持久化；結果未明不得關閉，仍可進既有恢復頁。成功且列表刷新後關閉視窗、提示結果；刷新失敗留原視窗重試，不重做已提交操作。關閉後焦點回頁首（App）或所選分頁／頁首（Web），撤權／換帳號／目標消失時不顯示失效內容。

工程驗證：Web 2,464 項、Mobile 1,740 項與工具 48 項通過；643 項 Web 環境案例略過，不算通過。根 check／contracts、Web build 與三平台 bundle 匯出通過；涵蓋點擊區、取消／防重送、失敗／失權、最後封存空分頁、完整計數／跨頁、四語卡片與 axe。沒有更動 API、儲存 schema、排序或原帳務／草稿恢復。
