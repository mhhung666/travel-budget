# 我的旅行：Web／Mobile 共同設計

更新：2026-11-03。UX-T1／UX-T2 已提交（`402c2321`），UX-T3 裝置／使用者驗證待執行。雙欄摘要、14px 圓角與同構載入占位已接入 Web／App，已通過本輪程式審查與 Web 元件瀏覽器驗收；原生裝置與完整流程仍依 UX-T3 待驗。完成摘要與當時工程結果見 [archive](../archive/README.md)。

## 共同資訊與操作

| -------- | --------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 頁首     | 我的旅行、建立旅行、加入旅行；空列表只顯示一組建立／加入                    | Web 移除建立 FAB；App 保留既有全域記一筆                     |
| 分頁     | 水平「旅行／已封存」，未封存包含已結束旅行；計數用完整授權資料              | App 分頁載入，不用已載入筆數充當總數                         |
| 主卡片   | 完整名稱 → 階段 → 日期／目的地／人數 → 我的分攤／待收付                     | 兩端卡片不顯示本人預算，旅行內預算入口保留                   |
| 導覽     | 整卡主入口包含空白；右上更多、底部快捷優先接受各自範圍的操作                | Web 主區 Link 開行程；App Pressable 開概覽                   |
| 快捷     | 已結束且本人餘額絕對值至少 0.01 → 查看結算；其他未封存 → 記一筆；封存無快捷 | 都只開頁／表單，不直接寫帳                                   |
| 更多     | 含旅行名的可及名稱；封存／取消封存先確認本人範圍                            | Web 選單含既有複製邀請；App 可捲動底部 sheet，分享仍在旅行內 |
| 本機工作 | 未讀／讀取失敗不顯示零，不把待送／待確認當草稿總數                          | App 在分頁下保留單列入口；Web 沿用自己的離線入口             |

沿用 T 的列表／quick-add 排序與本地 date-only 規則。日期缺一端明示，無日期顯示尚未排定；目的地無值就省略。階段與封存、本人餘額分開，零餘額不推論全團結清。完整名稱與幣別／非零小數可讀，不靠 hover、縮字或固定高度裁切。

## 互動與恢復

- 整卡主入口與更多／快捷分開，不嵌套 button／Link，也不以容器 onClick 攔截子操作。Web 的主 Link、App 的主 Pressable 覆蓋整張外框，內容層不攔截觸控，更多與快捷置於上層；點內容及卡內空白開旅行，點控制項只執行該項操作。主入口保留完整旅行資訊的可及名稱，快捷帶文字，更多讀屏名稱含旅行名。
- 封存只整理本人列表，一般成員與未結清旅行皆可操作；不刪除／退出／撤權、不改其他成員帳務／草稿。取消零寫入，送出防重複。
- App 沿用 `PersonalArchive` 的 review／sending／pending、E SQLite 與原 UUID；未知結果不可任意關閉或換 UUID，恢復入口保留。成功後刷新失敗只重讀，不再寫入。
- Web 沿用既有絕對封存狀態 mutation，失敗留確認供手動重試，沒有 App 的 journal／UUID。不要將兩端恢復能力寫成相同。
- 還原最後封存仍停在所選分頁及空狀態；成功關閉後焦點回 App 頁首、Web 所選分頁／頁首。撤權、換帳號、目標消失時不留私人內容。
- 首次載入、更新中、失敗、離線分清；保留舊列表不代表仍有操作權。保留虛擬化、下拉、載入更多及跨頁分組；更新／封存依 T 規則重設頁面。

## 版面尺度

沿用各端語意色與品牌綠；中性卡片、低陰影，不使用 hover 位移。待收／待付有文字，不只靠紅綠。

主區按壓時，底色與陰影由最外層卡片呈現，包含右側更多及底部快捷所在的完整外框；主區不再有獨立的實色圓角面板。Web 主連結本身與整卡同寬同高，移除原左側獨立圓角連結；同時關閉預設觸控高亮及 iOS 長按連結浮層（`-webkit-touch-callout: none`），以 pointer 事件管理按壓，放開、移出、捲動取消、失焦或開啟原生選單時清除；僅精細滑鼠支援 hover 陰影，鍵盤主區焦點顯示整卡外框。App 以主區按下／放開更新外卡陰影與底色，失焦清除按壓狀態。更多與快捷仍保留各自的按壓／焦點樣式與事件，主入口只有一個，容器不另外綁定導覽。無位移或縮放；Web 延用減少動態效果設定，App 即時切換樣式。

| 項目       | 規格                                                                                                                 |
| ---------- | -------------------------------------------------------------------------------------------------------------------- |
| 排列       | Web 與載入 skeleton 一致：小於 768px 單欄、768px 起兩欄、1024px 起三欄；App／iPad 維持單欄與內容最大寬，大字級可直排 |
| 間距／圓角 | 間距 4／8／12／16／24／32，卡片內距及卡間 16、分組 24–32；旅行列表卡片圓角 14、控制項 12                             |
| 字級       | 頁標題 24、卡片名稱 18／600、我的分攤 20／600、待收付金額 16、輔助 14；尊重系統縮放                                  |
| 觸控／焦點 | 目標至少 48×48 邏輯單位，相鄰操作至少 8；焦點框清楚且不裁切                                                          |

共享規格與案例，各端分別實作；不互相 import Web／React Native source，也不把 UI 放進 contracts。不新增封面、搜尋或統計入口填版面。

## 卡片簡化（2026-11-03）

### 已採用的方向

採用使用者選定的「雙欄摘要」與 14px 卡片圓角。旅行資訊、財務摘要、操作列維持三區；更多只占標題列，日期與財務使用全寬。狀態取消膠囊、列表移除本人預算、金額只搭一個 ISO 幣別碼；本人零餘額只顯示「目前無待收付」。完整卡面維持主入口，開啟提示與快捷合為一列。

```text
┌─────────────────────────────────┐
│ 202701 滑雪                  ⋯  │
│ 即將出發                        │
│ 2027/1/12 – 1/18                 │
│ 日本 · 3 位成員                 │
│                                 │
│ 我的分攤       │ 待收           │
│ 27,897.92 TWD  │ 6,149.19 TWD    │
├─────────────────────────────────┤
│ 開啟旅行 ›            記一筆    │
└─────────────────────────────────┘
```

### 兩端共同呈現

| 項目       | 新規格                                                                                                                                                                                                  |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 標題／更多 | 名稱 18／600，完整換行；更多 48×48，與名稱至少間隔 8。只有標題列預留更多空間，以下內容使用全寬。                                                                                                        |
| 狀態       | 改為 14 級低強調文字，取消膠囊。未封存顯示原階段；已封存且已結束只顯示「已封存」。已封存但仍旅行中／即將出發／未排定時，顯示「已封存 · 原階段」，不把封存推論為旅行結束。                               |
| 日期／人數 | 各占一行、字級 14；目的地與人數以 `·` 分隔，無目的地省略。中文完整起日，同年可省略迄日年份，同日只顯示一次；跨年保留兩年。部分／無日期沿用現有明示，保留 date-only 與四語格式，禁止從旅行名稱擷取日期。 |
| 我的分攤   | 左欄標籤 14；金額 20／600，採等寬數字。數字搭一個明確 ISO 幣別碼，例如 `27,897.92 TWD`，不再同時顯示 `NT$`。狹窄時允許幣別換行，金額不得截斷或縮字。                                                    |
| 待收付     | 右欄標籤 14；非零金額 16，顯示「待收／待付＋完整金額＋ISO 幣別碼」。本人餘額恰為零只顯示「目前無待收付」，不顯示重複的零，也不寫「全團已結清」。0.01／0.06 等小額照常保留，不套顯示歸零門檻。           |
| 本人預算   | 從列表卡移除；Web 原旅行內摘要／預算入口、App 原預算頁保留。不補逐卡查詢，也不以留白占位維持不存在的資訊。                                                                                              |
| 操作列     | 左側低強調「開啟旅行 ›」作為整卡導覽提示，右側輕描邊快捷；同列、高至少 48、間隔至少 8，可因大字級換行。僅一條淡分隔線，取消獨立的第二個快捷區。封存仍保留左側提示，無記帳／結算快捷。                   |
| 外觀       | 卡片圓角 14（Web 14px／App 14 邏輯單位）、控制項圓角 12、內距與卡間 16；中性實色底、細邊框、低陰影。品牌綠用於快捷／旅行中或即將出發階段；金額維持正文色。沿用兩端深淺語意色，不新增封面或進度條。      |

雙欄以可用內容寬度等分，間隔 12，右欄淡直線與內距 12。App 的「單欄」指卡片列表排列，卡內摘要預設仍為雙欄；遇大字級、長幣別或極大金額容納不下時，摘要依「我的分攤 → 待收付」改直排並移除直線，不縮字、不截斷。Skeleton 套用相同重排規則。

幣別顯示的簡化只影響此卡片；沿用既有金額精度、數字分組、四語與後端數值，不更動全站共用 formatter、帳本或小數規則。讀屏讀出完整數字與幣別；零餘額仍只描述本人。

保留原整卡 Link／Pressable 覆蓋與獨立控制項；左側「開啟旅行」是提示，不另建第二個焦點。更多與快捷是上層同級控制，點擊只走自己的既有流程。已結束且本人餘額絕對值至少 0.01 仍顯示「查看結算」，其他未封存仍顯示「記一筆」，封存確認／恢復機制不變。

### Skeleton 與實卡同構

- **每端共用自己的卡片版面骨架**：外框、內距、標題／更多、狀態／日期／人數、主金額／待收付、操作列使用相同區塊與間距；loading 只替換區塊內容，不另做不同高度與膠囊排列。不同平台不互相 import UI。
- Web 頁面 skeleton 同步移除舊外層實色卡，保留真正頁首、分頁、分組標題位置；使用與列表相同的容器寬度及 1／2／3 欄斷點。分頁計數未知時顯示占位，不假設為 0。App 首次載入改為單欄同構占位，保留頁首及原本機工作入口。
- 首次未知資料用中性的名稱一行／中等金額寬度，不偽造目的地、狀態或分組年份。已選封存分頁的占位不畫右側快捷；資料未知的通用占位可保留該區空間。長名稱、極大金額與動態字級仍允許實卡自然增高，**不承諾所有資料零位移**，也不以固定高度裁切。
- 背景刷新維持原卡與既有更新提示；載入更多只在列表尾端顯示占位，不清空已載入內容。錯誤／離線沿用明確訊息，不無限停在 skeleton。
- 占位無可點擊控制、不進 Tab／VoiceOver；列表以單一「載入旅行中」狀態播報。減少動態效果時靜態顯示，取消不必要的掃光與循環動畫。

### 落地與驗收

Web 與 App 已各自共用卡片外框／版面區塊，實卡與 skeleton 同步調整。Web 摘要以卡內可用寬與等寬數字的 `ch` 尺度自動重排，只量測兩欄是否同列以控制分隔線；App 以 `onLayout` 的實際內容寬、字級及金額長度判斷雙欄。背景更新保留原卡；App 下一頁占位留在尾端。占位靜態、無互動且不進讀屏焦點，只留單一載入狀態。沒有新查詢、API、持久化或帳務修改。

工程驗證：新增 30 項回歸；Web 2,622 項通過（672 項依既有設定略過）、Mobile 1,965 項＋工具 48 項通過；根 `pnpm check`（含契約／型別／lint／格式）、`pnpm build`、`pnpm export:check` 與 Expo 相容性檢查通過。本輪審查補齊 iOS 載入提示的單次主動播報，Android／Web 沿用單一 live region，避免每張 skeleton 重複通知。

Web 元件驗收：以實際 `TripCard`／`TripsPageSkeleton`、產品樣式與 Inter 字型，在隔離 Chromium 測試頁檢查四語 × 320／390／768／1280px × 深淺色 × 100%／200% 字級 × 一般／長文字／大額／載入，共 256 組，未見橫向溢出或可見文字裁切；目視核對桌面、手機寬度與大字級截圖。一般卡片與 skeleton 保留同構區塊，兩欄不足時直排。主區／邊界、更多／Esc 回焦、記帳、結算與 Enter 操作各自觸發單一目標；封存占位無互動，桌面一般案例 axe 的 WCAG A／AA 自動檢查無違規。

本輪工程與元件驗收完成，可提交。上述瀏覽器案例使用固定測試資料與導覽回呼替身，不是完整登入／真後端流程；未執行 Safari、iPhone／iPad、VoiceOver 或使用者任務驗證，環境缺少可用的 iOS Simulator，Android 仍待驗。原生 mock 與三平台匯出不算裝置證據，UX-T3 不因此結案。

後續整合／裝置驗收仍須確認：正常／載入的外框、欄寬及主要區塊對齊；有無預算不改卡片結構；封存零餘額與非零小額都可辨認；長名稱、長目的地、大額、不同幣別、部分／跨年日期、四語與 200% 字級不遮蓋。測 320／390／768／1280 寬度及深淺色，逐項點主區、更多、快捷與邊界，確認焦點與單一導覽不回歸。實作時執行下列 UX-T3 工程與裝置檢查。

## UX-T3 待驗證

驗收資料固定包括：零旅行、全封存、一般／封存各超過一頁、旅行中／即將出發／已結束／部分日期／無日期、長名稱／同名、零分攤零餘額、本人待收／待付、不同基準幣及離線／錯誤／未知結果。

- **防誤觸行為**：依序點卡片主區、快捷、更多與邊界；每次只產生目標操作，開更多不導覽、開記帳不提交、按取消不封存。跨卡片連續操作不沿用上一趟目標。
- **閱讀與無障礙**：320／390 CSS px、桌面約 1280px、iPhone／iPad 大字級；四語 `zh`／`zh-CN`／`en`／`jp` 與深淺色。名稱、金額、按鈕不遮蓋、不截斷；Tab／Enter、Esc 與 VoiceOver 可辨認主區、快捷和更多並返回合理焦點。Android 驗收需另列實際狀態，不以匯出取代。
- **任務驗證目標，非既有成果**：找至少 5 位未參與設計的使用者，用相同資料比較現況與提案，交替測試順序；完成「開指定旅行、記一筆、加入旅行、查看結算、封存再還原」。記錄首次點擊、誤入頁面、返回次數及是否需提示；每個任務至少 4/5 無提示完成，所有人都能區分建立旅行與記帳，零非預期提交。未達標時優先調整文案與熱區，不只換顏色。
- **工程檢查**：實作時跑受影響的導覽、卡片、分頁、封存／恢復行為測試與各 App 必要檢查；涉及 workspace／契約再依 [開發規範](../DEVELOPMENT.md) 執行完整驗證。卡片簡化的工程結果見上方「落地與驗收」；UX-T1／T2 的歷史結果見 [封存摘要](../archive/README.md)。裝置與使用者驗證另由他人執行。
