更新：2026-11-06。狀態：CD0 共用資料／相容後端已實作，工程檢查與獨立審查分開記錄；CD1 Web、CD2 App 已實作，待獨立審查與實際畫面驗收；CD3–CD4 未開始。Web 日卡 UI-W、App UI-M 已納入對齊實作，尚未視為畫面驗收通過。這份文件是兩端版面與跨日規則的唯一規格；既有多選／恢復規則見 [活動多選刪除](ITINERARY_BATCH_DELETE.md)。

## 目標與範圍

- Web／App 使用相同資訊順序、操作分區、名稱與跨日語意；Web 窄版和 App 必須用同一組資料逐項對照，不能只統一文案。
- 活動仍歸屬開始的每日行程；完整內容只存一筆，結束日可顯示導回原活動的提示。日期不明時不假裝已知。
- 先共用後端與 Web，再 App，最後兩端延續提示與聯合驗收。跨日多選 BD3、整天改期、多日住宿管理、時區換算／飛行時長、自動建立空白日不在本輪。

## 跨日顯示與編輯

以 1/12 22:25 出發、1/13 00:20 抵達為固定對照案例：

```text
Day 1 · 1/12  出發                         本日設定 ▾
本日備註……
──────────────────────────────────────────────────
當日活動 · 1 項                 選取活動  ＋新增活動
22:25         ✈ CX469 TPE–HKG                     ⋯
翌日 00:20      1/12 出發 → 1/13 抵達
```

```text
Day 2 · 1/13  東京                         本日設定 ▾
↳ 接續前一天
  00:20 抵達 · CX469 TPE–HKG       查看原活動 →
──────────────────────────────────────────────────
當日活動 · 4 項                 選取活動  ＋新增活動
00:30         住宿活動……                           ⋯
```

時間語意：

- 當日結束：保留兩行起／迄時間，不額外貼「跨日」徽章；翌日使用「翌日 00:20」，不單獨用 `+1` 或顏色傳達。
- 超過一日：有日期時顯示明確日期，未設旅行日期時用「第 N 天」；顯示完整起訖摘要，無障礙名稱也包含日期關係。
- 航班／交通摘要用「出發 → 抵達」，其他活動用「開始 → 結束」。未設定開始或結束時間顯示「時間未定」，不補 00:00、不計算時長；僅知道日期也能表達。
- 舊資料未確認結束日：保留既有時間，若結束時間小於開始時間則加「結束日期待確認」；管理員可進入原編輯器確認，一般成員看相同狀態。不得直接顯示翌日或產生延續提示。

兩端活動表單的時間區統一依序為「開始時間 → 結束時間 → 結束於 → 起訖摘要」，位置在活動基本資訊附近；桌面可並排，窄版依序垂直。`結束於` 提供「當日／翌日／其他日期」，舊資料另保留「未確認」。旅行無日期時「其他日期」改選「第幾天」。新建預設當日；結束時間早於開始時提出可操作的翌日建議，由使用者採用，不自動改動。允許明確選擇相同日而較早的當地時刻，不憑兩個時鐘值判錯。

跨國際換日線可能當地日期更早；資料模型預留有號日差，「其他日期」能表達較早的日期，摘要顯示真實日期。這類活動不套「接續前一天」提示。起訖均為使用者填寫的當地日期／時間，沒有時區資料時不推算 UTC、先後時長或「正在進行」。

## 延續提示規則

- 只從已明確設定正向跨日的活動投影；開始日仍以原時間排序。中間日顯示「接續 Day N · 活動名稱」，結束日補結束時間與「抵達／結束」，跨多日不錯標成「前一天」。
- 提示不計入當日活動數、不加入全選／15 項上限，也沒有編輯／刪除／附件的第二套入口；多選模式隱藏提示。只有提示的日仍可顯示「尚無當日活動」及新增入口。
- 同日有多個提示時，已知結束時間在前並依時刻排序，其他依來源 Day／活動原順序穩定排列；不和本日活動混算。
- 點「查看原活動」切到來源日並定位／強調原列，鍵盤與閱讀器焦點跟隨；App 可開原活動詳情並保留返回位置。跳轉仍經過現有未保存／未提交選取守衛。
- 只對已建立的日期卡片產生提示；不補空日、不延長旅行日期。超出旅行範圍仍在原活動顯示完整結束日期並提醒。
- 修改時間／結束日、刪除活動／來源日、修改旅行起日後，來源及所有相關日重新計算。目的日刪除不刪原活動；來源已失效時移除提示並提供可理解的返回結果。
- 不另存提示副本，不改支出、票券及照片歸屬，不自動擴大照片關聯的時間範圍；公開讀取只由既有可公開欄位投影，不能帶出訂位碼或私有附件。

## 資料、相容與影響盤點

日日期仍由旅行開始日＋dayNumber 推導；CD0 為活動新增日差，CD1 已接 Web 顯示／編輯，不憑兩個時鐘值推定跨日。

CD0 已新增可空的 `endDayOffset`（相對來源日的整數日差）：0＝當日、1＝翌日、負值＝較早的當地日期、null／舊資料缺欄＝未確認。以 date-only 運算推導日期，不受裝置時區／夏令時間影響。日差採 **−3650 至 +3650（含）整數**，沿用 Day 1–3650 的十年尺度作單次跨度上限；日差不受旅行長度或已建立日期卡限制，來源日加日差可以超出旅行或早於 Day 1。這不是時長限制，不比較兩個當地時鐘。無日期時保留相對日差，不虛構日期。

## CD0 實作與交接

- MongoDB 欄位為 `activities.endDayOffset`，Web DTO／輸入為 `end_day_offset`，v2／contracts 為 `endDayOffset`；讀取缺欄一律代表未確認，不由起迄時間推定翌日。`itineraryActivityTiming` 共用純 date-only 換算與未知警示，沒有時區／時長判斷；[共同 fixture](fixtures/itinerary-cross-day.json) 涵蓋同日、翌日、多日、較早日期、未知、閏日／跨年、缺時間與無旅行日期，Web／App 測試讀同一份資料。
- 新增省略欄位儲存 null；單筆更新與 Web 整日覆寫依穩定活動 ID 保留原值，顯式 null 才清除。新值經共用範圍驗證，變動沿既有 revision／trip fence 協調；保留票券、照片／支出關聯與原排序。模型、成員／公開 DTO、Native 閱讀／edit context 同步，公開仍移除訂位碼與票券。筆記新增維持未確認，不新增猜測；AI 日期證據與匯出文案已由 CD1 接入。
- 編輯 context 新增可選 `capabilities.activityEndDayOffset: true`；舊回應缺能力時，新版表單必須停用新日期輸入並提示需要更新後端，不能試送後靜默降級（表單接 CD1／CD2）。舊 App 忽略 additive 讀取欄位，其省略更新保留日期。
- BD1／BD2 歷史預覽的 target 為 strict decoder，因此預覽及刪除命令新增可選 `includeEndDayOffset: true`；只有主動要求時 targets 才帶日期。舊請求的預覽形狀不變，完整原活動（包含日差）仍參與確認 hash；改日差會使先前確認失效。CD1／CD2 須帶此選項並呈現日期，不能只加入一般閱讀時間。
- 命令 schema 不替省略欄位補預設；原 frozen payload、UUID hash、終局 receipt 不改寫。重開 SQLite 的舊／新 body、原 UUID 查詢／重送及不可變舊 receipt 保持相容；未知結果不換 UUID。Web 讀取快取 buster 更新，舊讀取資料重抓；獨立 outbox／confirmed journal 不清除。
- 部署後端前執行 Web `pnpm migrate:up`，新增 migration `20261106120000-itinerary-end-day-offset.js` 只把缺欄活動補 null，可重跑、不猜日期、不改 revision／receipt。此處未執行遠端 migration；既有刪除預覽若因 raw document 補欄導致 hash 不同，須重新預覽確認。`down` 會移除包含明確值的新欄位，回滾前須停用跨日寫入並接受失去已設定結束日，不能在仍有新操作待恢復時降版。

驗證：新增 **60 項**回歸（Web 共用規則／相容 31、App 共同 fixture／能力與 SQLite 重啟 20、隔離交易 9）；全套 Web **2,697**、Mobile **2,022** 與工具 **48** 項通過，另有 696 項 Web opt-in／外部服務案例在一般套件中跳過。`test:mobile-api` 已另行執行本機可丟棄 replica set 的真 HTTP／DB、既有行程維護及批次交易，核對固定 UUID、舊 receipt、並行衝突、單筆／整日保留與 migration，工具結束已清除容器。根 frozen install、contracts 生成／檢查、check、build、Expo 相容性與三平台匯出通過；快取 buster 更新後另跑 23 項離線恢復測試，未清除 outbox。

獨立程式審查、Web／PWA 與 iPhone／iPad 實際操作待後續階段。CD0 沒有新增日期表單／延續提示，不宣稱畫面已對齊；未部署、未執行遠端 migration。

## CD1 Web 實作與交接

- 活動草稿與單筆表單已傳遞日差：新建預設當日、舊活動缺欄仍為未確認；共用時間區依序為開始、結束、結束於、摘要。其他日期支援負日差，未設旅行日期改填第幾天；非法／超出日差上限會停用保存，時鐘倒序只提供可採用的翌日建議，不自動更改或拒絕明確當日。儲存失敗保留草稿。Web 表單與同版 Server Actions 一起部署；獨立 App 的後端能力判斷已由 CD2 接入。
- 成員／公開日卡、活動選取與無障礙名稱、批次確認、CSV／Markdown／PDF 共用日期摘要：翌日有文字、其他日有完整日期／Day N，缺時間不補午夜，未知不冒充當日／翌日；旅行範圍外仍保留日期並提示。批次新預覽及新提交帶 `includeEndDayOffset: true`，接受衝突後更新選取內的日差；既有持久化 body 及原 UUID 恢復不加新欄位。CSV 現改為每個原活動一列，增加活動／開始日期時間／結束日期時間欄，空日保留一列；PDF 時間摘要改全寬以容納日期，不重複活動。公開 DTO 仍由既有白名單排除訂位碼與私有票券。
- AI 只保留能在來源找到、且包含日期／同日／翌日等日曆證據的日差；僅有兩個時鐘、證據不存在或無法辨識則保持未確認，預覽可手動修正後才確認。證據摘錄不寫入活動；舊匯入 payload 省略欄位保持省略，原操作重試不重複新增。這是保守的證據檢查，仍須使用者核對，不宣稱 AI 日期推論已獨立驗收。
- 今日／下一活動提示沿用來源日開始時間、照片自動關聯仍依每日行程範圍；沒有新增時區／進行中或跨日照片推論。CD2 App 日期／版面已接續實作，見下方；CD3 延續提示、CD4 實際驗收尚未開始。

## 驗收重點

- **日期**：22:25→翌日00:20、當日較早時刻、跨月／跨年／閏日、跨多日、負日差、等時刻、起／迄任一未填、旅行無日期、跳日、旅行範圍外、舊資料未知；改旅行開始日期後兩端一致。
