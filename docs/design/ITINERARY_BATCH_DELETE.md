# 行程活動多選刪除

更新：2026-11-06。BD1 Web 同日多選與共用後端已實作，獨立程式審查通過，實際畫面待驗；BD2 App 同日多選已實作並通過獨立程式審查與自動複驗，iOS 操作待驗；BD3 跨日暫緩，僅保留候選，不列入本項目結案條件。第一版解決「同一天挑掉數個活動」，不將活動與整天刪除混成同一操作。

## 現況與範圍

- Web `ItineraryDayCard` 已新增管理員同日選取，原日／單活動選單保留；cookie actions 與 Native 新批次 adapters 共用 `itineraryBatchDelete.ts`，在父旅行交易中核對活動 revision、確認上下文與票券退役。
- App 2B／2C 已有單筆日／活動確認及 SQLite 原 UUID 恢復；BD1 擴充 Web IndexedDB confirmed journal，BD2 擴充 App TripEntry／SQLite envelope，不重寫舊日／單活動 RPC。批次不是迴圈呼叫單筆刪除。
- 目前 Expense 的 `itineraryDays` 關聯到日，沒有活動級帳務關聯。活動刪除保留日、日說明、其他活動、支出、相片及既有個人成就紀錄；只移除所選活動及其票券參照，實體檔案依既有引用檢查／清理工作處理。
- 同日第一版支援 1–15 個不同活動 ID，沿既有每日新增容量；若歷史資料超過 15，明示單批上限，不能悄悄截斷全選。全選活動也保留空的行程日，不自動刪整天。

桌面操作列放在當日日卡底部，必要時在內容區內 sticky；窄版 Web／App 使用底部操作列，預留安全區與底部內容空間，不能蓋住最後一列或旅行導覽。大字級允許兩列排列，不縮小文字硬塞。示意只表達操作，實作沿兩端既有元件與語意色彩。

選取模式中，整列的主要動作是勾選／取消；暫停該日新增、編輯、單筆刪除、拖曳、票券開啟及帶入成就等會與勾選競爭的操作，不在 checkbox label 裡嵌套其他按鈕。保留辨識所需的文字。Web 用 Tab／Space 操作、Esc 先關確認再退出選取；App 提供可見入口，不依賴長按。閱讀器播報日期、時間、名稱、勾選狀態與選中數量；觸控目標至少 44 點。

第一版換日／離開頁面時，有選取則詢問「離開並清除選取？」；取消選取本身直接清空，不需要額外警告。選取只留當頁記憶體，不跨旅行、帳號、登入世代保留。確認後已保存的未知操作走恢復流程，不把離開頁面當成取消伺服器提交。

## 衝突、權限與恢復

- 選取以穩定的日／活動 ID 為準，不用名稱或排序 index；保存選取時 revision 與必要的日日期／標題快照。檢視時比較最新資訊，目標活動修改或日日期／標題改變要顯示差異、保留選取並明確重新確認；不默默換成最新 revision。未選活動修改不構成衝突。
- 任一所選活動已消失，整批不提交；標明消失項目，讓使用者明確移除失效選取、重新檢視餘下項目。正在確認時收到更新也使確認失效，不自動擴大／縮小刪除集合。
- 管理員降權停止寫入；撤權／換帳號遮蔽私有資料及清除未提交選取。送出及結果查詢重新授權；拒絕查詢不代表先前提交失敗。
- 確認後先保存環境／帳號／旅行、UUID 及凍結請求，再送出；本機保存失敗不送出。送出中停用雙擊；未知結果顯示「正在確認刪除結果」，不能當作已刪、取消或改選後換 UUID 重送。
- 重啟／重連只查同 UUID。查得 committed 才更新畫面，rejected 才解除阻塞並恢復選取；not_found 只允許使用者明確原 UUID／原內容重試。沿用帳號 429 原絕對期限，不繞過其他待處理工作。
- 不提供假「復原」toast。真正撤銷需要軟刪除、票券保留期限與並行衝突設計，另案處理。

## 共用後端與契約設計

新批次服務接收 actor、trip、day、UUID、`targets[{activityId, expectedRevision}]` 及確認上下文的 opaque revision。上下文涵蓋日日期／標題與所選活動／附件影響，不以整日 revision 阻擋無關活動變動。預覽／提交均在授權快照／交易內核對；重複 ID、跨旅行／跨日、空集合及超量皆拒絕。

提交在一個父旅行 fence 交易中，先驗證全部前置條件，再一次移除目標活動，更新日 revision／時間、退役未引用票券並保存整批終局收據。不能 catch 單筆錯誤後繼續提交前面已刪項目。任何基礎設施錯誤整批回滾；業務拒絕可保存無刪除效果的終局收據。結果只含原 UUID、日／活動 ID、數量及狀態，不持久保存標題／訂位碼／附件 key。查回原終局不依活動是否還存在。

票券影響區分「移除參照」與「實體清理」：刪除集合以外仍有引用就保留檔案。Native 現有 context 沒有活動級附件數，第一版用明確文字說明，不拿全日附件數冒充；若要顯示數字，新增後端白名單計數，並納入確認 revision。外部 R2 清理仍交持久工作，不能放在可重試交易回呼內。

已提供獨立批次 schema／結果，避免改壞既有六種單筆 command 與已保存 payload 的解析。現行路徑：管理員 `POST /api/v2/trips/:id/itinerary/activity-deletions/preview`、`POST .../activity-deletions`、`GET .../activity-deletions/:uuid`。preview 僅讀取、不建立刪除請求；Web cookie actions 與 Native bearer adapters 共用同一服務，各維持認證方式。輸入／回應以 contracts schema 及產生的 OpenAPI 為準。

UUID 使用既有 actor／UUID 唯一性與指紋原則，加入批次操作種類／目標集合，目標排序正規化；跨旅行或同 UUID 不同內容衝突，不能重寫收據。沿用既有交易剩餘期限、no-store、公開分享隔離、清理及快取失效規則。新舊 App 能並存，單筆端點／receipt 向下相容。

## 驗收門檻

- UI：零／部分／全選、同名不同時段、取消確認保留、全刪留空日、換日離開提示；重繪／排序／新增列不移動選取或默選。深淺色、窄版、大字級、鍵盤／閱讀器與操作列不遮擋。
- 交易：三筆中任一 revision 失效、消失、降權皆零刪除；未選活動改動不阻擋；全部成功只一張收據、一組刪除效果。同 ID 重複、跨旅行、同 key 不同內容被拒。
- 關聯：保留日、支出／相片與非目標活動；共用票券不誤刪，未引用票券退役只一次，R2 失敗不把已提交批次當成失敗。
- 恢復：確認前保存失敗、雙擊、提交成功但丟回應、完成保存失敗、刷新／重啟、429、換帳號、降權後 lookup 拒絕、查詢 not_found 原內容重試；實測與自動測試分列，不用 mock 宣稱裝置通過。
- 必跑受影響兩端測試、contracts generate/check、隔離 replica set 原子性／競態與真 HTTP 恢復，再依 workspace 規則跑完整檢查。測試只在自行建立的可丟棄本機資料庫執行，不操作正式資料。

## BD1 實作與交接

- `ActivityBatchDeletionProvider` 只在行程頁保存單日記憶體選取；日／活動 ID 與選取時版本固定，其他列排序或新增不擴大集合。預覽重讀日日期／標題及所選內容；活動／整日消失可明確移除失效選取，變更須採用最新資料並再次檢視。資源 `NOT_FOUND` 不永久停用選取；只有明確權限拒絕會清除並遮蔽選取。確認中快取更新會使確認失效。操作列保持文件流中的空間，窄版黏在旅行導覽上方並允許換行；實際版面仍待驗。
- 嚴格 input 為 `{ dayId, targets: [{ activityId, expectedRevision }], client_request_id, expectedContextRevision }`，最多 15 筆且不重複。preview 另回 `missingIds`／`changedIds` 與無票券 key 的摘要。上下文包含當日日號／推算日期／標題與選中活動完整快照；日內容與未選活動修改不造成衝突。actor／UUID 沿用 `itinerarymutationrequests` 主鍵，排序及 ID 大小寫正規化，不改六種單筆 command／舊 receipt。未新增資料欄位或索引，無 migration。
- Web 新操作沿用 `confirmedWebWrites` 的環境／帳號隔離、同旅行保留及帳號絕對等待期限；送出前保存凍結內容。重啟／重連只查原 UUID，`not_found` 顯示明確「重試原刪除請求」，由使用者再次觸發原內容；查詢拒絕保留未知操作。終局落盤後才釋放旅行保留，舊 Web 日／活動 mutation 也尊重該保留。批次 journal 不保存標題／訂位碼／票券 key；既有 query cache 形狀未改，不調整持久查詢 buster。
- `historyNavigation.ts` 自 Web 根 provider 啟動後記錄同文件各歷史項目的位置，保留 Next 路由 state；跨帳號重掛不重設追蹤器。未提交選取取消返回／前進／多步跳轉時，按帶方向的實際距離還原，原跳轉及補償事件均不交給路由；相同 URL 的不同歷史項目也可區分。換日、連結離開與關閉頁面保留既有提示。

工程驗證：新增 24 項 Web 回歸與 15 項隔離批次交易案例；Web 全套 2,646、Mobile 1,965 與工具 48 項通過。一般測試依既有設定略過 687 項隔離／外部案例；另在可丟棄本機 replica set 實跑批次 15＋既有單筆行程 30 項，並通過完整 `test:mobile-api` 真 HTTP／DB 工具。frozen install、根 check／contracts、Web build 與三平台匯出通過。額外 Expo 相容性檢查未通過：現有 expo、constants、image-manipulator、image-picker、router、splash-screen 比目前建議版本落後 patch；本輪未調整 App 依賴。
