## 1. 背景與問題

目前個人統計提供總支出、日期區間、花費長條圖、分類統計與標籤統計。這些內容能重排既有支出資料，但不足以回答使用者真正關心的問題：

- 哪一趟旅行、哪個分類最花錢？
- 平均每趟旅行花多少？
- 異常支出發生在哪一天？
- 看見問題後，能否繼續篩選、查看或編輯原始支出？

現有互動主要是日期切換、圖表 tooltip 與明細 accordion，圖表、分類、旅程和明細之間沒有連動，因此頁面偏向靜態報表，而不是可探索的分析工具。

## 2. 改版目標

### 2.1 產品目標

1. 使用者進頁後能在第一屏理解目前支出狀況與每趟旅行的平均花費。
2. 使用者能從期間、圖表、分類或旅程逐步縮小範圍，找到構成支出的原始資料。
3. 統計內容凸顯「旅行記帳」特色，而不是一般記帳 App 的分類報表。
4. 手機與桌機維持相同分析能力，手機操作不依賴 hover。

### 2.2 非目標

第一階段不建立通用 BI 報表系統，也不包含：

- 使用者自訂圖表或欄位
- 跨使用者排名
- AI 自由文字分析
- 公開分享個人支出統計
- 新的預算模型
- CSV／PDF 統計報告

## 3. 核心設計原則

- **先結論，再探索**：摘要先回答結果，圖表與明細再解釋原因。
- **避免錯誤比較**：旅行沒有固定消費週期，不用任意等長期間暗示支出好壞。
- **篩選狀態一致**：摘要、圖表、分類、旅程與明細必須使用同一組篩選條件。
- **逐層揭露**：第一屏不顯示大量逐筆資料；點選後再展開明細。
- **可回到原始資料**：分析結果不是終點，支出明細應能連回可查看或編輯的位置。
- **個人口徑明確**：金額只計算目前使用者的分攤金額，不顯示整筆群組支出。

## 4. 第一階段範圍（MVP）

第一階段交付以下四個能力：

1. 四個洞察摘要
2. 可互動的花費趨勢圖
3. 分類／旅程分析切換

### 4.1 預設期間

- 首次進入預設選擇「本月」。
- 提供快捷選項：本月、近 30 天、今年、全部。
- 其他日期範圍收進日期選擇器，不在首屏平鋪。
- URL query 保存期間與分析維度，使重新整理與返回頁面後能還原狀態。
- 「全部」必須有明確選中狀態，不以兩個空白日期欄位暗示。

### 4.2 統計摘要

首屏顯示四張不可篩選的摘要卡：

| 指標 | 定義 | 輔助資訊 |
| --- | --- | --- |
| 總支出 | 篩選期間內個人分攤總額 | — |
| 平均每趟支出 | 總支出 ÷ 期間內有支出的旅程數 | 無旅程時顯示 0 |
| 旅程數 | 期間內至少有一筆個人分攤支出的旅行數 | — |
| 支出筆數 | 期間內含個人分攤的支出筆數 | — |

「平均每趟支出」使用有支出紀錄的旅程作為分母，比篩選區間的日曆天數更符合旅行記帳情境。
不同旅程的目的、長度和消費型態差異很大，因此不提供固定週期增減比較。

### 4.3 旅程洞察卡

摘要下方顯示可操作的洞察卡：

| 洞察 | 定義 | 點擊行為 |
| --- | --- | --- |
| 最高支出旅程 | 目前日期範圍內個人分攤總額最高的旅程 | 切到旅程維度並篩選該旅程明細 |
| 最高支出分類 | 目前日期範圍內個人分攤總額最高的分類 | 切到分類維度並篩選該分類明細 |
| 最高支出標籤 | 有標籤資料時，累計個人分攤總額最高的標籤 | 切到標籤維度並篩選該標籤明細 |

- 卡片顯示洞察名稱、對象、金額與筆數，不以模糊的百分比製造比較結論。
- 點擊卡片時清除圖表時段篩選，確保明細能完整解釋卡片上的聚合金額。
- 再點已選取的洞察卡會維持該篩選；使用分析區的 active filter 或「清除篩選」解除。
- 沒有標籤資料時不顯示空白標籤卡，卡片區自動調整欄數。
- 洞察僅使用規則式聚合，不產生因果、節省或超支等未被資料支持的文字。

### 4.4 花費趨勢圖

- 支援金額／筆數切換。
- 支援日／週／月粒度；日期改變後重新選擇合理的預設粒度。
- 桌機 hover、鍵盤 focus 與手機點擊都能顯示同一份 tooltip 資訊。
- 點擊資料柱後，選取該時段並同步更新下方分析與明細。
- 已選資料柱具有明確視覺狀態，並提供「清除圖表篩選」。
- 圖表只呈現目前篩選期間的絕對金額或筆數，不疊加上一期資料。
- Y 軸金額格式需支援小於 1,000、千、百萬等量級，不固定顯示 `0k`。
- 小螢幕顯示大量日／週資料點時，維持可辨識與可點擊的柱寬，圖表改以橫向捲動承載，
  不將資料柱壓縮成細線。

### 4.5 分析維度

趨勢圖下方提供 tabs：

1. 分類
2. 旅程
3. 標籤（有資料時才顯示）

每一列至少顯示：

- 名稱
- 個人分攤總額
- 占目前篩選總額比例
- 筆數
- 相對長度進度條

預設按金額由高至低排列，另提供金額、筆數、名稱排序。點擊一列後：

- 趨勢圖切換為該維度的資料。
- 下方明細只保留符合條件的支出。
- 頁面顯示可移除的 active filter。

旅程列另提供前往該旅程支出頁的操作。若旅行已封存，仍可檢視，操作方式沿用既有封存規則。

### 4.6 支出明細

- 預設顯示前 5 筆，提供「查看全部」。
- 支援日期與金額排序。
- 每筆顯示描述、日期、旅行、分類與個人分攤金額。
- 點擊後開啟既有支出檢視／編輯流程，不另建第二套表單。
- 無符合資料時提供清除目前篩選的 CTA。

## 6. 篩選與互動狀態

建議以單一狀態描述頁面：

```ts
interface PersonalStatsFilters {
  preset: 'month' | 'last30Days' | 'year' | 'all' | 'custom';
  startDate?: string;
  endDate?: string;
  interval: 'day' | 'week' | 'month';
  metric: 'amount' | 'count';
  dimension: 'category' | 'trip' | 'tag';
  dimensionValue?: string;
  selectedPeriodStart?: string;
  selectedPeriodEnd?: string;
}
```

互動優先順序：

1. 日期範圍決定全部資料集。
2. 圖表選取可再縮小明細期間。
3. 洞察卡或分析列選取可加入分類、旅程或標籤條件；洞察卡會先清除圖表時段。
4. active filters 必須可個別移除，也要能一次清除。
5. 切換主要日期時，清除不再有效的圖表選取；維度選取可在仍有資料時保留。

## 7. 資料契約建議

`StatsData` 由 server action 一次回傳已聚合資料，避免前端持有所有跨旅程支出後自行計算。

```ts
interface PersonalStatsData {
  period: {
    startDate: string | null;
    endDate: string | null;
  };
  summary: {
    totalAmount: number;
    totalExpenses: number;
    tripCount: number;
    averagePerTrip: number;
    topCategory: {
      category: string;
      amount: number;
      percentage: number;
    } | null;
  };
  timeline: {
    interval: 'day' | 'week' | 'month';
    dataPoints: Array<{
      startDate: string;
      endDate: string;
      amount: number;
      count: number;
    }>;
    totalAmount: number;
    totalCount: number;
  };
  categories: PersonalStatsDimension[];
  trips: PersonalStatsTripDimension[];
  tags: PersonalStatsDimension[];
}

interface PersonalStatsExpensePage {
  items: PersonalStatsExpense[];
  nextCursor: string | null;
}
```

資料注意事項：

- 所有金額維持基準幣 TWD，沿用個人分攤金額口徑。
- 日期以使用者本地日曆日為準，不以 UTC 字串截斷推導日期。
- 一筆支出有多個標籤時，可分別出現在各標籤統計；標籤總額不得被解讀成互斥占比總和。
- 百分比的分母為目前篩選總額；總額為 0 時回傳 0。
- Server 端每次最多回傳 20 筆明細，以排序值與支出 `_id` 組成游標；日期、金額排序及
  旅程／分類／標籤／期間／指定支出篩選均在 MongoDB 完成。
- 明細頁由獨立 action 查詢，不包含在主要統計契約；切換排序或篩選時使用獨立 query key。
- 不提供固定週期比較；旅行支出頻率不規律，跨期增減容易造成錯誤解讀。

## 8. Loading、錯誤與空狀態

- 日期或維度改變時保留上一份內容，局部顯示更新狀態，避免整頁 skeleton 閃爍。
- 初次載入才顯示完整 dashboard skeleton。
- 查詢失敗時保留可用的舊資料，顯示錯誤與重試操作。
- 完全沒有個人支出時，說明統計會如何產生，並提供「記一筆」CTA。
- 篩選後無資料時，顯示目前篩選摘要與「清除篩選」CTA。
- 部分區塊無資料時只處理該區塊，不隱藏整個 dashboard。

## 9. 可及性與在地化

- 圖表須提供文字摘要或可鍵盤操作的資料點；不可把資料只畫在 SVG。
- 選中狀態不得只靠顏色。
- 圖表控制使用正確 button／toggle 語意與可見 focus。
- 圖示若為裝飾需設為 `aria-hidden`。
- 日期、貨幣與數字沿用目前 locale；新增文案需同步四語 catalog。
- 動畫遵守 `prefers-reduced-motion`。

## 10. 效能與查詢

- 日期範圍進入 query key；主要維度維持前端互動狀態。
- 純前端排序、已載入維度切換不應重複查詢。
- 日期快速切換可依 TanStack Query cache 重用資料。
- MongoDB 查詢需檢查 `trip`、`splits.user`、`date` 的索引與 explain 結果。
- 不把無上限的跨旅程支出明細送到瀏覽器。
- 圖表資料桶數設定合理上限；超長期間使用月粒度。

## 14. 進階規則式洞察規劃

### 14.1 目標與原則

進階洞察應回答「這筆支出為什麼值得注意」，而不是再顯示一次排行榜。第一版維持可解釋、
可驗證的確定性規則，不使用 AI 生成結論，也不推測消費好壞。

- 只描述資料事實，例如「交通占這趟旅程支出的 52%」。
- 不使用「浪費」、「不正常」、「應該節省」等價值判斷。
- 不與上一期或其他旅程比較，除非旅程目的、天數等比較口徑已被明確定義。
- 每張卡必須顯示觸發原因、計算口徑及可查看的原始明細。
- 樣本不足時不產生洞察，避免一至兩筆支出形成誇大的百分比。
- 同一件事只顯示一次；預設最多顯示三張，依重要性與可信度排序。

### 14.2 第一批規則

以下門檻為初始產品假設，實作時集中定義於規則設定，不散落在 UI 元件內。

| 規則 | 觸發條件 | 卡片範例 | 點擊後篩選 |
| --- | --- | --- | --- |
| 旅程分類集中 | 單趟至少 3 筆支出；最高分類金額占該趟總額 `>= 45%` | 「東京行的交通占總支出 52%」 | 旅程＋分類 |
| 單筆支出集中 | 單趟至少 3 筆支出；最高單筆占該趟總額 `>= 35%` | 「機票是首爾行最大單筆支出，占 41%」 | 旅程＋指定支出 |
| 集中消費日 | 單趟涵蓋至少 2 個有支出日期且至少 4 筆；最高日占該趟總額 `>= 40%` | 「大阪行有 46% 支出集中在 7/12」 | 旅程＋日期 |
| 支出分布平均 | 單趟至少 4 筆、至少 3 個分類；最高分類占比 `< 40%` | 「京都行的支出分布在 4 個分類」 | 旅程 |
| 標籤集中 | 單趟至少 3 筆已標籤支出；同一標籤涵蓋 `>= 50%` 的旅程支出 | 「北海道行有 58% 支出標記為滑雪」 | 旅程＋標籤 |

規則補充：

- 百分比金額一律採目前使用者的個人分攤金額。
- 金額為 0 的支出不參與集中度規則。
- 標籤不是互斥維度，一筆支出可同時被多個標籤計入；卡片需註明標籤占比不可相加。
- 「支出分布平均」與「旅程分類集中」互斥，同一旅程只會出現其中一種。
- 第一版不做「高於平常」、「比其他旅程貴」等個人基準規則；不同旅程的目的和天數不可直接類比。

### 14.3 洞察排序與去重

每次最多顯示三張，避免頁面再次變成資訊牆。候選洞察依下列順序選取：

1. 單筆支出集中
2. 集中消費日
3. 旅程分類集中
4. 標籤集中
5. 支出分布平均

同一旅程預設最多顯示兩張。若「單筆支出集中」和「集中消費日」由同一筆支出觸發，
只保留單筆支出洞察。若多張同類型洞察同時符合，優先顯示：

1. 占比超過門檻最多者。
2. 占比相同時，個人分攤金額較高者。
3. 金額仍相同時，採固定 `tripId`／日期排序，確保畫面與測試穩定。

### 14.4 資料與狀態前置

現有 `StatsData` 已包含旅程、分類、標籤及逐筆明細，可支援規則原型；但正式版本應在
server 端計算候選洞察，避免未來明細改為游標分頁後，前端只拿到部分資料卻產生錯誤結論。

建議新增資料契約：

```ts
type StatsInsightType =
  | 'trip_category_concentration'
  | 'single_expense_concentration'
  | 'spending_day_concentration'
  | 'balanced_category_distribution'
  | 'trip_tag_concentration';

interface StatsInsight {
  id: string;
  type: StatsInsightType;
  tripId: string;
  titleKey: string;
  values: {
    tripName: string;
    amount?: number;
    percentage?: number;
    category?: string;
    tag?: string;
    date?: string;
    expenseDescription?: string;
  };
  filter: {
    tripId: string;
    category?: string;
    tag?: string;
    startDate?: string;
    endDate?: string;
    expenseId?: string;
  };
}
```

目前頁面一次只能選一個 `dimension`，無法精準表示「旅程＋分類」或「旅程＋日期」。
實作進階洞察前，需先把單值維度狀態升級為可組合的 filters：

```ts
interface StatsDetailFilters {
  tripId?: string;
  category?: string;
  tag?: string;
  periodStart?: string;
  periodEnd?: string;
  expenseId?: string;
}
```

圖表、分析排名、active filters、URL query 與明細必須共用這組條件。點擊洞察後應捲動至
明細、逐項顯示可移除的條件，並提供一次清除全部條件的操作。

### 14.5 顯示與互動

- 區塊標題使用「值得注意」，與現有「旅程洞察」排行榜區隔。
- 卡片顯示一句結論、主要數字及「根據 N 筆支出」的樣本說明。
- 卡片可展開「如何計算」，顯示分子、分母及觸發門檻。
- 點擊主要操作套用完整複合篩選並前往明細，不只切換單一分析維度。
- 若原始支出已刪除或目前日期條件不再涵蓋該洞察，移除失效卡片，不保留空殼。
- 洞察不足三張時不使用較弱規則補滿；整區無候選時不顯示。
