# 個人統計維護說明

> 狀態：功能、效能與響應式驗收完成
> 最後驗證：2026-07-30
> 頁面：`/stats`

本文件只保留個人統計特有的資料口徑、查詢限制與後續觀測事項。使用者功能概覽見
[FEATURES.md](./FEATURES.md)，共通 UI 規則見 [UI_UX_SPEC.md](./UI_UX_SPEC.md)，實作歷程請查
`git log -- docs/PERSONAL_STATS_DASHBOARD.md`。

## 現行能力

- 日期範圍支援本月、近 30 天、今年、全部與自訂期間。
- 摘要包含總支出、平均每趟支出、旅程數與支出筆數。
- 趨勢圖可切換金額／筆數和日／週／月粒度。
- 分類、旅程、標籤、圖表時段與指定支出可組成篩選條件，並由 URL 還原。
- 規則式洞察可展開計算依據，點擊後套用相同條件至明細。
- 支出明細由 server 游標分頁，每頁 20 筆，可依日期或金額排序並進入既有編輯流程。
- 初次載入、背景更新失敗、無支出和篩選無結果都有對應回饋與下一步。

## 資料口徑

- 個人統計只計算登入者在 `Expense.splits` 中的 `shareAmount`，不是整筆群組支出。
- 金額沿用系統基準幣 TWD；日期使用本地日曆日，不能以 UTC 字串截斷推導。
- 平均每趟支出以期間內「有個人分攤支出」的旅程數為分母。
- 標籤不是互斥維度；同一筆支出可計入多個標籤，標籤占比不可相加解讀。
- 旅行沒有固定消費週期，因此不顯示任意上一期增減或價值判斷。

主要聚合由 [`getStats`](../src/actions/stats.actions.ts) 在 server 完成；client 只處理在地化標籤、
顯示與互動。個人與群組統計的差異見 [ARCHITECTURE.md](./ARCHITECTURE.md) §4.7。

## 查詢契約

- 日期範圍、粒度與複合篩選必須納入 TanStack Query key。
- timeline 回傳未在地化的日期邊界、金額與筆數；日／週最多 366 個資料桶，長期間改用較粗粒度。
- 明細使用排序值與 `_id` 組成複合游標；不得把無上限的跨旅程支出送到瀏覽器。
- 日期明細依賴 `splits.user + date + _id` 複合索引；相關 migration 是
  [`20260730090000-add-personal-stats-expense-index.js`](../migrations/20260730090000-add-personal-stats-expense-index.js)。
- 金額排序需在 `$unwind` 取得登入者的 `shareAmount` 後執行，目前會產生預期的 blocking sort。
- 統計回傳形狀或 query key 改變時，必須同步更新 persisted query cache 的 `PERSIST_BUSTER`。

診斷工具：

```bash
pnpm stats:explain -- --user <ObjectId>
pnpm stats:benchmark
```

`stats:benchmark` 只允許名稱含 `benchmark`、`bench` 或 `test` 的隔離資料庫，預設測完刪除。
可用 `--sizes 500,2000` 和 `--db <name>` 調整測試級距與資料庫。

## 規則式洞察

洞察只描述可由資料驗證的事實，不推測消費好壞。門檻與規則版本集中在程式碼，異動門檻時
必須升規則版本，讓正式環境的匿名命中率可分開比較。

| 規則 | 最低樣本與初始門檻 |
| --- | --- |
| 旅程分類集中 | 單趟至少 3 筆；最高分類占比 `>= 45%` |
| 單筆支出集中 | 單趟至少 3 筆；最高單筆占比 `>= 35%` |
| 集中消費日 | 至少 2 個支出日且 4 筆；最高日占比 `>= 40%` |
| 支出分布平均 | 至少 4 筆、3 個分類；最高分類占比 `< 40%` |
| 標籤集中 | 至少 3 筆已標籤支出；同標籤占比 `>= 50%` |

- 金額為 0 或樣本不足時不產生集中度洞察。
- 每次最多三張、同趟最多兩張；同一事件命中單筆與日期規則時只保留單筆。
- 排序必須穩定；相同輸入永遠產生相同結果。
- 匿名事件只能記規則版本、類型、候選數量區間與操作，不得包含 ID、名稱、描述、日期或金額。

## 驗證基線

2026-07-30 在同一 MongoDB 叢集的隔離資料庫，以 500、2,000、10,000 筆合成支出各預熱一次、
量測五次：

| 支出數 | 主查詢中位數 | Server 計算 | 日期明細 | 金額明細 |
| ---: | ---: | ---: | ---: | ---: |
| 500 | 21.4ms | 3.0ms | 4.7ms | 5.1ms |
| 2,000 | 75.0ms | 12.9ms | 9.4ms | 10.6ms |
| 10,000 | 257.8ms | 33.9ms | 3.3ms | 33.7ms |

所有查詢均命中 `splits.user_1_date_-1__id_-1`，未出現 `COLLSCAN`。日期明細維持近似固定成本；
金額排序與全部期間主查詢隨資料量線性成長。真實帳號接近 10,000 筆或持續超過產品延遲門檻時，
再評估預聚合或正規化個人分攤資料。

介面另以 500 筆資料驗證 360×800、390×844、412×915、手機橫向、1440×900 與 200% zoom
等效 viewport；無頁面級水平溢出，URL 還原、原生日期欄、圖表橫滑、safe area 與 reduced
motion 均通過。正式站登入 smoke test 亦已通過。iOS Safari 與 Android Chrome 的原生日期
選擇器及手勢手感仍屬部署後真人裝置抽查。

## 後續事項

- 累積足夠匿名事件後，檢查洞察命中率與點擊率；只有資料支持時才調整門檻。
- 真實資料量或延遲跨過上述基線時，重新執行 benchmark／explain，再決定是否改查詢架構。
- 國家／城市維度、預算達成率、跨年度趨勢與分析匯出屬新功能，排程時移至
  [ROADMAP.md](./ROADMAP.md)，不要在本文件累積新 Phase 規格。
